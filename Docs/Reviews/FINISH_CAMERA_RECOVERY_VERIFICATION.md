# 결승 카메라와 체크포인트 복귀 화면 검증

`feature/match-results-tally`의 `f8ba7b4` 이후 클라이언트 연출 변경이다. 결과 순위와 경기 전환은 기존 서버 상태를 읽는다.

## 편집 위치

| 위치 | 역할 |
| --- | --- |
| `WBP_MatchResults` → `PodiumCameraKeys` | 결승 소켓 기준 카메라 위치·시선 이동량과 FOV 차이, 키 진행률을 편집한다. 시작 키는 높은 결승 시점에서 그대로 시작한다. 집계판 이후 짧게 멈췄다가 내려오고 순위판 표시 중 최종 자세에 고정된다. |
| `MWMatchResultsWidget.h/.cpp` | 복제된 결승 포트로 기준 변환을 만든다. 후보 시점과 이동 구간의 가시성·충돌을 먼저 검사하고 한 배율로 재생한다. 막히면 이동량을 줄이고 적합한 경로가 없으면 선택된 시점에 머문다. 완료 후 기존 결과 화면의 정리 경로로 카메라를 해제한다. |
| `MWGameplayPlayerController.cpp` → `ApplyGameplayInputMode` | 결과 단계에 들어올 때 입력 모드 갱신이 결승 카메라를 이전 주행 Pawn으로 덮던 경로를 제거했다. |
| `WBP_MatchPanels` → `RecoveryPanel`, `RecoveryMarker`, `RecoverySweep` | 하단 상대 앵커, 표식 모양과 전체 화면 펄스의 색을 편집한다. 기존 상단 타이머 위젯은 트리 안에서 접어 이전 바인딩의 GUID를 보존했다. |
| `MWGameplayHUDSubsystem.h/.cpp` → `CheckpointRecoveryLayout` | 기존 복귀 상태의 첫 관측에서 화면 펄스를 시작한다. 표식은 해당 창의 참가자 색을 쓴다. 지면을 확인한 보조 가이드와 차량 슬롯을 화면에 투영하고 입력 해제 직전에 선분을 흩뜨린다. 가이드 투영과 펄스 시간은 HUD 설정이 소유한다. |

### 로컬 WBP 편집값

결승 카메라 키는 다음과 같다. 위치·시선은 기준 결승 카메라에 대한 결승 소켓 로컬 cm이며 FOV는 기준값과의 차이다.

| 진행률 | 위치 XYZ | 시선 XYZ | FOV 차이 |
| ---: | --- | --- | ---: |
| 0.000 | 0, 0, 0 | 0, 0, 0 | 0° |
| 0.085 | 0, 0, 0 | 0, 0, 0 | 0° |
| 0.430 | −410, 180, −780 | 35, 20, −60 | −3° |
| 0.720 | −560, 255, −1030 | 20, 75, −75 | −5° |
| 1.000 | −650, 310, −1085 | 0, 125, −70 | −5° |

`RecoveryPanel`의 앵커와 피벗은 `(0.5, 0.91)` 및 `(0.5, 0.5)`다. 둥근 표식은 1920×1080 디자인 캔버스에서 92×14 단위를 쓰고 뷰포트에 맞춰 축소된다. 펄스 색은 선형 RGBA `(0.91, 0.30, 0.10, 0.15)`다. C++은 이 색을 뷰포트 전체에 적용해 캔버스 바깥 영역까지 채운다. 보조 슬롯은 지지면을 확인한 위치의 로컬 가이드이므로 서버 복귀 위치 계산에 참여하지 않는다.

## 3인 PIE와 원본 대조

Cua Driver로 리슨 서버와 별도 PIE 클라이언트 창 두 개를 실행했다. 뷰포트는 1920×1080, 1280×720, 800×482였다. 2라운드부터 34초 동안 호스트의 1920×1080 백버퍼를 저장했다. 결승까지 짧게 재현하기 위해 PIE 목표 점수는 550점으로 설정했고, 선택·배치를 거쳐 생성된 코스를 사용했다. 일반 통과는 트리거 앞 약 6.7m에서 실제 차량에 전진 입력을 넣었다. 복귀는 차량을 코스 아래에 두어 낙하를 유도했고, 남은 참가자의 체크포인트와 결승은 검증용 위치 지정으로 판정을 재현했다.

| 장면 | 영상 기준 | ProjectMW 관측 및 차이 |
| --- | --- | --- |
| 일반 통과 | 한국어 녹화 F33829에 체크무늬, 게이트, 주행차, 슬롯이 한 화면에 보인다. | #43 부근에 P1이 주행 입력으로 체크포인트를 통과해 100점을 받았다. 복귀 표시가 올라오지 않았다. 이 코스의 런타임 체크포인트는 별도 체크무늬 메시를 갖지 않아 화면 정렬 기준은 통과 이벤트다. |
| 복귀 | Switch F8260에 하단 표식, F8268–8284에 따뜻한 색 화면 효과, F8320–8332에 흰 슬롯 파편이 보인다. | #109에 P1의 하단 표식, 화면 펄스, 고리와 흰 슬롯 세 개가 보인다. #113에서 펄스가 내려가고 #120에서 슬롯이 흩어진다. #125에는 복귀 표시가 사라졌다. 서버의 주행 허용 복구까지 P1은 0.80초, P2는 0.84초였고 P3는 주행을 유지했다. 원본의 펄스는 표식 뒤에 시작한다. ProjectMW는 첫 관측에서 함께 시작하며 원본보다 색이 옅고 주행 시점을 유지한다. |
| 가산 | F29109부터 제목, F29164에 첫 체크포인트 가산이 시작된다. | 호스트 첫 가산은 집계 시작 약 0.45초 뒤였다. #183에서 막대와 차량 배지, 점수가 함께 오르는 것을 확인했다. 마지막 보너스는 P2가 받았다. |
| 누적 순위 | F29998에 순위 표시, 2.57초 뒤 F30152에 집계판이 내려간다. | #201에서 P1 550점, P2 450점, P3 300점과 순위를 확인했다. 세 창에서 점수판 뒤의 결승 카메라가 유지됐다. 호스트의 누적 순위 단계는 약 0.49초로 원본보다 약 2.08초 짧다. |
| 시상 | F30152에 높은 배경이 보이고 F30180 부근에서 낮은 트랙 시점, F30304에서 1위판이 처음 보인다. | #204에 높은 배경, #222에 접근 중, #251 부근에서 우승차 회전과 1위 진입, #257에서 정착을 확인했다. 첫 1위 공개의 상태 표본은 판이 내려가고 약 3.60초 후로, 원본 2.53초보다 약 1.07초 늦다. 2·3위의 첫 로그는 1위 대비 약 +0.27초, +0.36초였고 세 창에서 누적 1위 FRED가 표시됐다. 기존 결과 화면은 시상에서 유지된다. |

### 결승 카메라 실측

호스트에서 누적 순위 직전과 첫 결승 장면은 같은 위치와 FOV였다. 1위판이 들어올 때까지 카메라는 10.63m 낮아졌고 정착까지 월드 공간에서 총 13.02m 이동했다. 테스트한 코스에서 가시성 검사 결과는 세 창 모두 이동 배율 1.00이었다. 캡처 구간에서 카메라가 구조물을 뚫거나 시점이 Pawn으로 돌아가는 장면은 관측하지 못했다.

| 호스트 표본 | 카메라 높이 Z | FOV | 결승 피스 기준점 화면 좌표 | 같은 결승 피스의 두 번째 표본 |
| --- | ---: | ---: | --- | --- |
| #202 누적 순위 | 8,920cm | 64° | (960.0, 781.0) | (960.0, 717.3) |
| #203 결승 진입 | 8,920cm | 64° | (960.0, 781.0) | (960.0, 717.3) |
| #251 1위 진입 구간 | 7,857cm | 59° | (1018.9, 824.6) | (1007.3, 752.0) |
| #256 정착 시작 | 7,835cm | 59° | (1031.3, 830.1) | (1018.4, 756.6) |

원본은 판이 사라지고 약 0.47초 뒤에 더 낮은 트랙 시점을 보여 준다. 이번 경로는 높이를 천천히 낮추면서 결승 체크무늬와 두 구조물을 화면에 유지한다. 1위 차량은 화면 안에 남고 시상 이후의 계속 버튼과 경기 개요는 보류 상태다.

### 같은 점수 데이터의 최종 레이아웃

| 뷰포트 | 점수판 경계 | 막대 바닥 y | 바닥 간격 | 차량 배지 지름 |
| --- | --- | ---: | ---: | ---: |
| 1920×1080 | (220.0,196.0)–(1700.0,977.0) | 972.0 | 5.0px | 88.0px |
| 1280×720 | (147.2,131.4)–(1132.8,650.6) | 647.3 | 3.3px | 58.6px |
| 800×482 | (70.1,88.2)–(729.9,435.2) | 433.0 | 2.2px | 39.2px |

1080p 렌더에서 위젯 경계를 좁힌 뒤 밝은 글리프 픽셀을 측정했다. 제목은 79px, 등수 숫자는 97·98·99px다. 제공 영상의 약 77px와 100px에 가깝다. 원본의 점수판 바닥은 y999이고 ProjectMW는 y977이다. 실제 PIE 표본은 3인이다.

정착 메달 중심과 지름은 1위 (378,309)/180px, 2위 (532,608)/147px, 3위 (629,845)/132px다. 제공 영상의 (386,244)/254px, (458,618)/203px, (503,865)/166px와 비교하면 이 빌드의 메달은 더 작고 가로로 펼쳐 있다. 메달과 카드의 진입 경로, 기존 이름판과 우승차의 화면 내 크기는 이 커밋에서 재편집하지 않았다.

실제 렌더는 33.929초 동안 448장, 평균 **13.17fps**였다. 프레임 간격 중앙값은 81ms, 최대 277ms였으며, 인접한 원시 픽셀 CRC 중복과 프레임 요청 누락, 저장 유실은 0건이다.
