# 낙사 조기 복귀와 차량 점멸 통합 검증

검증 브랜치는 `fix/respawn-recovery`, 원격 `main` 기준은 `5a4006d`다. 낙사 복귀 `e645ea0`과 점멸 `7b2d9e7`에 들어 있던 변경을 적용했다. 낙사 브랜치에 함께 기록됐던 가드레일 조사 문단과 증거는 해당 원본 브랜치에 보존했다.

## 통합 동작과 수정 위치

| 역할 | 적용 위치 |
| --- | --- |
| 실제 복귀 시점 | `MWGameplayGameMode`와 `MWTrackRuntimeSubsystem`이 접지 없는 하강을 확인하고, 기존 서버 체크포인트 복귀를 사용한다. `FallRecoveryProbeInterval`의 빌드 기본값은 1초다. |
| 착지 여부 | `MWVehicleMovementComponent`가 차량 중력, 현재 속도, 차체 충돌과 설치 트랙으로 예상 하강 경로를 검사한다. 아래 트랙에 닿을 수 있으면 물리 착지를 기다리고, 빈 공간에서는 기존 코스 하한에 닿기 전에 복귀할 수 있다. |
| 복귀 직후 점멸 | `MWVehiclePawn`과 `MWVehiclePawnNetwork`가 서버 복귀에 성공했을 때의 시간을 복제한다. 각 창의 차량 이동 스냅샷이 그 시각에 도착한 뒤 차체와 바퀴를 점멸한다. |

## Cua Driver 3인 PIE

UE 5.8.4에서 통합 코드의 `MWEditor Win64 Development` 빌드를 통과했다. Snow 리슨 서버와 클라이언트 두 창에서 각각 트랙을 설치하고 실제 출발 슬롯의 `Racing` 진입을 확인했다. 확정 코스는 시작 조각, 리프트, 오르막 왼쪽 곡선, 하프파이프 왼쪽 곡선, 결승 조각으로 구성됐다.

낙하 시작 조건은 P2(DOUG) 또는 P3(MAMMOTH)를 해당 출발 슬롯 높이에서 코스 전체 XY 경계 밖으로 한 번 옮겨 맞췄다. 이후 기존 차량 물리와 서버가 낙하·복귀·복제를 처리했다. 사용한 빌드의 GameMode 기본값은 1.0초로 확인했다. 복귀 시간은 낙하 시작부터 서버가 다시 실제 출발 슬롯의 XY를 기록한 첫 표본까지다.

| 원격 차주 | 정상 속도 복귀 시간 | 복귀 위치 첫 표본 |
| --- | --- | --- |
| P2 | **1.304초, 1.242초, 1.308초** | `(-2620, 525, 6055) cm` |
| P3 | **1.269초, 1.211초** | `(-2870, 375, 6071) cm` |

정상 속도 다섯 회의 범위는 **1.21~1.31초**, 중앙값은 **1.27초**였다. 복귀 직전 마지막 서버 표본의 Z는 약 5,257~5,406cm였고, 같은 코스의 기존 복귀 하한은 2,900cm였다.

P2와 P3의 반복 시험에서 호스트·원격 차주·다른 클라이언트 모두 **세 번 소등 후 계속 표시**됐다. 여섯 관측 경로의 최종 표시 복원은 첫 복귀 표본 뒤 약 **0.75~0.79초**에 기록됐다. 첫 소등 위치와 서버 복귀 좌표의 차이는 최대 **1.7cm**였다. 카메라 대상, 차체 충돌 모드와 원래 숨겨져 있던 메시의 최종 상태가 모두 유지됐다. P2 첫 시험에는 세 번째 소등 예정 구간을 건너뛴 **0.21초 표본 공백**이 있어 소등 횟수는 반복 시험 결과로 확인했다.

캡처용 P2 추가 실행은 세 창이 처음 소등된 시점에서 잠시 시간 배율을 낮춰 같은 상태를 촬영했다. 시간 표는 정상 배율 실행만 사용한다. 이 실행은 한 PC의 3인 PIE와 첫 체크포인트 전 복귀 범위다. 작업공간의 기존 아이템 소스 편집은 그대로 둔 상태에서 빌드했다.
