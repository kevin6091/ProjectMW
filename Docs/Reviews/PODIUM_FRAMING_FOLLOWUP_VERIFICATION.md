# 결승 접근 카메라와 시상 공개 검증

Client UI 변경이다. [e295274 결과](FINAL_RESULTS_READABILITY_VERIFICATION.md)와 공유받은 비교표의 차이를 실제 프레임에서 재확인했다.

## 변경 위치

| 위치 | 실제 변경 |
| --- | --- |
| `UMWMatchResultsWidget::BeginFinishShot` | 대체 위치를 고르기 전에 각 시작 위치에서 카메라의 시야와 이동 경로를 검사한다. 기본 경로가 막히면 기존 대체 위치에 설정한 높이에서 기본 X·Y를 재시도한다. 측면 후보는 이후에 확인한다. 이동 가능한 후보가 없으면 첫 가시 위치를 쓴다. 시상에서 가시 위치도 없으면 결승 카메라 없이 카드 표시 경로를 진행한다. |
| `UMWMatchResultRowWidget::SetPodiumEntry` | 화면 왼쪽까지 메달을 보내는 거리를 메달의 실제 레이아웃 폭과 위치에서 구한다. 기존에는 전체 판의 폭으로 메달도 함께 화면 밖으로 밀어내고 있었다. 현재 움직이는 렌더 좌표 대신 레이아웃 경계를 사용한다. 기존 WBP 바인딩이나 기하가 없을 때 기존 시작점을 사용한다. |
| `WBP_MatchResults` | 카메라 단독 2.44 → 2.34초, 시상 진입 구간 0.85 → 0.72초, 순위별 시작 간격 0.16 → 0.12초. 기존 카메라 키, 순위별 카드 디자인, 이름 크기, 차량 키, 점수판 열과 바닥 간격은 이어서 사용했다. |

카메라의 시야와 이동 체크는 코스 메시와 환경의 기존 검사 경로를 사용한다. 최종 점수 보관과 서버 단계 전환에는 변경이 없다. 다음 경기 개요에 쓰던 Continue 버튼은 이 프로젝트의 기존 시상 HUD에서 숨겨져 있다. 원본 영상은 F30319 부근에서 표시하지만 여기서는 현재 종료 입력을 그대로 사용했다.

## Cua Driver 3인 PIE 실측

호스트 1920×1062, 클라이언트 1280×720과 800×482에서 설원 4,000점 경기의 7라운드 집계를 확인했다. 트랙 선택·설치는 기존 요청을 실행했다. 첫 체크포인트는 스로틀로 통과했고 이후 판정 시험에서 차량을 각 실제 트리거에 넣었다. 세 창에서 일치한 최종 점수는 4,200/3,150/2,450점이었다. [완료된 세 창](Evidence/PodiumFramingFollowup/podium-three-windows.jpg)

완주 → 선착 보너스 → 누적 → 카메라 사이의 세 구간은 이전 2.034 / 3.080 / 2.493초, 이번 2.042 / 3.056 / 2.492초다. 후속 시상 운동만 앞당겼다. 일반 코스 세 창은 정면 `View=0`에서 시작하고 `TravelScale=1.00 SideScale=1.00`으로 같은 이동 경로를 사용했다. 다른 일반 코스에서는 길이·높이 배율 0.65와 옆 이동 1.00을 선택했다.

금·은·동은 이전 렌더에서 카메라 시작 뒤 약 2.79/2.92/3.08초에 각각 처음 식별됐다. 이번에는 약 2.47/2.63/2.75초였다. 원본 표본에서는 은메달의 일부가 먼저 들어오며 금·은·동 기준 2.40/2.35/2.48초에 보인다. 프로젝트는 금·은·동 공개 순서를 유지한다. 이름판과 이름의 첫 식별, 세 카드 정착을 각각 기록했다. 우승 차량은 기존 화면 앵커를 사용하고 이름판과 차량 외곽이 떨어지는 정도는 차량 모양과 뷰포트에 따라 다르다. [프레임 번호와 시간](Evidence/PodiumFramingFollowup/visible-milestones.csv)

호스트 실제 렌더의 단일 프레임을 사용했다. 1,142장, 평균 33.58fps, 프레임 간격 중앙값 29ms였으며 인접 프레임 CRC가 같은 경우는 없었다. 첫 식별은 렌더 해상도와 가시성 판독 기준의 영향을 받는다. 상태 로그의 `Screen=Winner`는 프레임 검토의 기준점으로만 사용했다. 원본과 코스·차량·뷰포트 비율이 달라 화면 좌표 일치는 검증 범위에 포함하지 않는다.

### 정면 가림 재현

PIE 월드의 복제되지 않는 임시 테스트 메시를 결승 카메라와 주시점 사이에 뒀다. 세 창에서 이 메시지를 포함하면 가시성 선이 막히고 제외하면 통과했다. 저장된 맵에는 적용하지 않았다. 첫 구현에서는 정면을 들어 올리면 시야 충돌 검사는 통과했으나, 결승에 연결된 조각의 화면용 메시 경계 상자들이 주시점을 감싸 모든 후보가 제외됐다.

결승에 연결된 조각에서 주시점을 포함하는 경계 상자는 경계만으로 후보를 탈락시키지 않도록 했다. 카메라 시작점이 상자에 들어가는 경우와 실제 가시성 충돌은 계속 탈락시킨다. 보정 후 세 창 모두 최종 시상에서 `View=6 TravelScale=1.00 SideScale=1.00`을 사용했다. 기본 정면 위치와 월드 X·Y가 같았고 Z만 1,380 Unreal 단위 높았다. 가림 조건에서도 최종 집계의 세 구간은 2.039 / 3.064 / 2.466초였다. ## 체크포인트 복귀

첫 시험에서는 호스트가 실제 스로틀로 체크포인트를 통과했다. 두 차를 서로 다른 위치에서 낙하시킨 첫 시도는 P1만 복귀 상태에 진입할 때까지 관측됐다. 재시험은 P1·P2를 같은 지지면 없는 공간에 조금 떨어뜨려 배치하고 두 소유자가 각자 복귀를 마칠 때까지 더 기다렸다. P1과 P2의 첫 활성 샘플은 0.800초와 0.793초가 남은 상태였다. P1은 첫 활성 샘플에서 약 0.813초 뒤 다시 조작 가능했고 P2도 같은 마지막 샘플에서 조작 가능했다. P3는 전체 관측 동안 복귀 상태가 없었다.

두 차주 화면에서 선수색 원형, 플래시, 월드 슬롯과 재출발 직전 흩어지는 슬롯 변을 확인했다. P3에는 펄스나 슬롯이 없었다. 원본 F8260~8348의 장면은 게이트가 여러 차량을 한꺼번에 옮기는 조건이다. 그 장면은 별도의 상단 숫자와 더 밝은 파편을 사용한다. 이번 검증은 두 개별 복귀가 겹치는 기존 ProjectMW 조건이며 숫자 카운트다운을 새로 표시하지 않았다.
