# 코스 착지 가능 여부에 따른 낙사 복귀

브랜치는 `fix/track-fall-recovery`, 기준 main은 `5a4006d`다. 기존 서버 판정은 코스 전체 최저점보다 `FallRecoveryDepth`만큼 아래까지 내려갈 때 동작했다. 첫 검증에서 같은 코스와 시작 좌표로 이 판정만 사용했을 때 복귀에는 2.13초가 걸렸고, 0.25초 설정으로 조기 판정을 켜면 0.29초에 돌아왔다. 체감 확인 후 새 기본값을 1초로 조정해 실제 복귀가 약 1.2초가 되게 했다.

## 수정 위치

| 위치 | 변경 |
| --- | --- |
| `MWGameplayGameMode.h/.cpp` | 기존 전체 코스 하한을 안전 판정으로 유지하고, 낙사 판정에 예상 경로의 트랙 접촉 검사를 추가했다. `MW\|Race`의 `Fall Recovery Probe Interval`에서 하강 유예와 재검사 주기를 편집한다. 조정한 기본값은 1초다. 0은 이전 하한 판정만 사용하는 설정이다. |
| `MWTrackRuntimeSubsystem.h/.cpp` | 접지 없이 계속 하강한 참가자만 검사한다. 타이머는 서버의 기존 차량별 경기 기록에 속하며, 접지·상승 시 해제되고 새 라운드에서 초기화된다. 복귀 위치 선택은 기존 체크포인트·출발 슬롯을 사용한다. |
| `MWVehicleMovementComponent.h/.cpp` | 차량의 현재 속도, 중력 배율, 낙하 속도 상한, 차체 충돌과 기존 `VehicleGround` 채널로 하강 궤적을 검사한다. 설치된 코스의 충돌과 만날 가능성이 있으면 실제 물리 처리를 기다린다. 직선 검사 구간의 높이 오차는 기존 접지 검사 거리에 맞춘다. |

설치된 트랙만 후보로 본다. 지형·장식에 맞으면 해당 액터 뒤도 계속 조회한다. 측면 접촉처럼 실제 충돌이 궤적을 바꿀 수 있는 경우 다음 검사에서 새 속도로 판단한다. 예측은 현재 충돌 위치를 사용한다. 움직이는 발판의 미래 위치를 별도로 시뮬레이션하지 않는다. 차체 위치·속도·입력이나 네트워크 상태를 예측 검사에서 수정하지 않는다.

## 최초 3인 PIE 실측

UE 5.8.4에서 `MWEditor Win64 Development` 빌드가 성공했다. Cua Driver로 Snow 테마의 리슨 서버와 클라이언트 두 창에서 각각 트랙을 설치했다. 시작 조각, 평지 직선, 오르막 오른쪽 곡선, 고가 왼쪽 곡선, 결승선으로 이어진 코스에서 세 창의 `Racing` 진입을 로그로 확인했다.

PIE 전용 계측에서 서버 차량의 시작 위치와 속도를 한 번 지정해 각 조건을 재현했다. 이후 서버 주행 물리가 착지와 복귀를 처리했다. 점프와 아래 트랙 착지에서는 첫 접지 기록 후 차량을 멈춰 캡처했다. 통제 비교에서는 같은 실행의 서버 설정을 `FallRecoveryProbeInterval = 0`으로 잠시 바꿔 기존 하한 판정만 사용한 뒤 기본값으로 복원했다.

| 조건 | 서버 게임 시간 기준 결과 |
| --- | --- |
| 호스트 P1 점프 | Z 6190.8cm에서 상승해 약 6345cm까지 올라갔다. 복귀 없이 1.282초에 진행 방향 노면에 다시 닿았다. |
| 원격 P3 아래 트랙 착지 | 트랙 옆 빈 공간의 Z 7400.0cm에서 노면을 향해 비스듬히 하강했다. 1.178초에 약 13.3m 아래 노면에 닿았다. 호스트와 P3 창에서 같은 착지를 확인했다. |
| 호스트 P1 빈 공간 낙사 | 코스 경계 바깥에서 Z 6101.0cm, 정지 상태로 하강했다. 새 판정은 0.286초에 출발 슬롯으로 복귀했다. 같은 위치와 속도에서 기존 하한 Z 4275.6cm만 사용하면 2.132초가 걸렸다. 두 시험 모두 P3 창에서도 돌아온 위치가 관측됐다. |

시간은 시작부터 서버의 첫 접지 표본 또는 첫 복귀 좌표까지다. 차량들이 멀리 떨어진 구간에서는 P2 창에 대상 차량이 복제되지 않아 P2의 해당 좌표 표본은 없다. 검증한 범위는 정적 트랙의 점프·하강·빈 공간 복귀이며, 움직이는 발판과 모든 테마 조합은 이번 계측에 포함되지 않았다.

## 약 1.2초 복귀로 조정

같은 Snow 3인 PIE의 서버 차량 P3을 코스 경계 밖 `(-2870, 17919.39, 6071) cm`에서 정지 상태로 떨어뜨렸다. 살아 있는 GameMode 설정만 바꿔 후보를 비교하고 시험 후 복원했다. 기존 차량은 낙사 판정을 0.25초마다 호출하므로 설정값과 첫 복귀 표본 사이에 최대 한 검사 구간 정도의 차이가 생긴다.

| 서버의 하강 검사 간격 | 낙하 시작부터 서버가 기록한 복귀까지 |
| --- | --- |
| 0.25초 | 0.461초 |
| 1.2초 | 1.379초 |
| 1.0초 | 1.195 / 1.108 / 1.270 / 1.093 / 1.163 / 1.170초. 중앙값 1.167초. |

최종 기본값은 1초다. 반복 시험에서 호스트와 P3 창이 출발 슬롯 복귀를 관측했다. P2 창에서는 이 차량의 해당 위치가 복제 범위 밖이어서 좌표 비교에서 제외했다. 비교 실측은 앞선 빌드의 GameMode에서 같은 필드에 1초를 적용해 수행했다. 기본값 변경 후 `MWEditor Win64 Development` 빌드도 성공했다.
