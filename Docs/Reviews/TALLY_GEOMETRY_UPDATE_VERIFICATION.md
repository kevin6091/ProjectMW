# 경기 점수판 채움 영역과 막대 배치 검증

기준은 `feature/match-results-tally@7cedd52`, UE 5.8.4, 기존 UVCS cs:82 작업공간의 결과 UI 로컬 인계본이다. 인계받은 점수·복귀·시상 분석과 `7cedd52-편집명세.md` 중 점수판 부분을 적용했다. 두 WBP의 변경 전 파일 해시는 기존 저점수 검증 기록과 일치했다. [기존 저점수 검증](RESULTS_LOW_SCORE_VERIFICATION.md)

## 편집 위치

| 위치 | 변경 |
| --- | --- |
| `WBP_MatchResults` | `TallyWidth`를 디자인 단위 1480에서 1520으로 조정했다. 3인 열 너비는 940을 유지하고 4인은 1252를 지정했다. `TallyStack` 상단 패딩 90→66, `TallyColumnExtent` 상단 패딩 12→0으로 채움 영역을 확보했다. 만점 열 위 등수와 간격을 확보하도록 제목의 Y 이동값을 −62, 로고 슬롯의 상단 오프셋을 −68로 편집했다. |
| `WBP_MatchScoreColumn` | `VerticalMeterExtent`의 높이 482→584, 상단 패딩 93→51을 적용했다. 기존 0점 바탕의 실효 높이를 유지하도록 `TallyBaseFraction`을 0.23에서 약 0.18983으로 바꿨다. 배지·숫자 슬롯과 글꼴을 재사용했다. |
| 같은 WBP의 `ScoreBar.WidgetStyle.FillImage` | 내부의 진한 윤곽이 들어 있던 채움 텍스처를 단색 `RoundedBox` 브러시로 바꿨다. 위쪽 모서리 반경은 각각 10 디자인 단위, 아래쪽은 0, 윤곽 폭은 0이다. 선수색은 기존 `SetFillColorAndOpacity` 경로에서 적용하며 비어 있는 막대 바탕은 기존 스타일이다. |
| `MWMatchResultsWidget.cpp`과 `.h`의 `SetTallyScore` | 이전 점수와 표시 범위를 함께 비교한다. 점수가 같고 표시 범위만 달라지면 채움과 마커 앵커를 갱신하며, 텍스트 포맷은 표시 숫자가 바뀔 때 계산한다. |

경기 목표, 서버 점수와 순위, 가산 애니메이션의 정지 순서, 경기 단계 전환은 기존 경로 그대로다. 4,000점을 분모로 한 양쪽 표본에서 세로 영역 확장 효과를 비교했다. 참고 영상의 경기 목표가 같은지는 확인되지 않아 비교용 목표를 런타임에 넣지 않았다.

## 3인 PIE 결과

Cua Driver로 설원 Listen Server PIE의 세 창을 열었다. 실제 뷰포트는 **1920×1062 / 1280×720 / 800×482**였다. 호스트에 1920×1080을 요청했으나 이 실행에서 창이 1062px 높이로 잡혀 같은 뷰포트에서 전후를 비교했다. 4인 화면은 동일 데이터의 로컬 표시 검증이며 실제 네트워크 경기는 3인으로 진행했다.

| 조건 | 결과 |
| --- | --- |
| 같은 4인 점수 3000 / 2300 / 2375 / 2650, 목표 4000 | 호스트에서 채움의 전체 영역은 473.9→574.2px, 점수 1점당 표시 높이는 약 0.091→0.116px로 늘었다. 막대의 위 경계 Y는 572.6 / 636.5 / 629.6 / 604.6에서 509.2 / 590.6 / 581.9 / 549.9로 이동했다. 좌표는 뷰포트 내부 픽셀이다. |
| 0 / 50 / 120 / 500점 | 세 창에서 배지와 숫자가 채색 영역 안에 들어갔다. 호스트의 0점 채색 높이는 전후 약 109px, 판과 막대의 하단 간격은 약 5px다. |
| 가운데 열을 포함한 만점 동점과 3인 누적 순위 | 세 창에서 제목과 등수가 겹치지 않았고, 세 참가자의 열 정렬도 유지됐다. |
| 점수 3000 그대로 표시 범위 4000→3000 | 채움률이 약 79.75%에서 100%로 다시 계산됐고, 표시 숫자는 `03000`이었다. 화면 격리 검증용 데이터에서만 범위를 바꿨다. |
| 채움 브러시 | 채색부 중간 높이에서 막대 폭의 3·5·8·11% 지점과 중앙을 비교했다. 변경 후 3개 뷰포트 × 4가지 색에서 비교 지점의 RGB가 중앙과 같았다. |
| 실제 방의 3인 라운드 집계 | 기존 서버 요청으로 트랙을 설치했다. 차량을 실제 결승 트리거에 놓고 기존 판정으로 300 / 150 / 50점을 받았다. 세 창에서 라운드 제목, 완주 점수, 선착 보너스, 누적 순위의 순서가 같았다. 캡처 후 다음 라운드의 트랙 선택으로 전환했다. |

실제 집계는 호스트에서 Cua Driver로 약 8.9초간 29장을 순서대로 저장했다. 중앙 표본 간격은 317ms로 화면 전환 확인에 사용했다. 네트워크 경기의 결승 진입과 복제는 실제 경로이며 결승선까지 전 구간을 수동 주행하는 시험은 이번 범위에 포함하지 않았다. 화면 비교는 기존 참가자 표식과 운전 HUD가 보일 수 있는 표시 전용 상태에 동일 데이터를 넣었다. 실제 라운드 집계의 화면 상태는 별도 로그에서 확인할 수 있다.
