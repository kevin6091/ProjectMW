# 체크포인트 복귀 차량 점멸 검증

`feature/respawn-blink`에서 `origin/main@5a4006d`의 복귀 경로를 사용했다. 서버가 체크포인트 텔레포트에 성공하면 지금의 서버 시각을 복제한다. 차량 이동 스냅샷이 그 시각에 도달한 뒤 각 창에서 차체·바퀴를 점멸한다. 새 경기 준비에서는 점멸 시각을 초기화한다.

## 수정 위치

- `MWVehiclePawn.cpp`에서 성공한 복귀를 기존 일반 텔레포트와 구분한다. 차량 외형 중 점멸이 직접 숨긴 메시만 다시 표시한다. 원래 숨긴 메시, 카메라, 차량 충돌과 입력은 기존 동작을 유지한다.
- `MWVehiclePawn.h`의 차량 기본값에서 지속 시간 0.9초와 토글 간격 0.15초를 조정한다.
- `MWVehiclePawnNetwork.cpp`에서 호스트·조작자·관전자에게 같은 시작 시각을 복제한다. 복귀 판정·좌표·속도 초기화는 기존 경로가 결정한다.

## 검증

UE 5.8.4 `MWEditor Win64 Development` 빌드를 통과했다. Cua Driver 3인 PIE에서 Snow 코스의 트랙 선택·서버 설치 검사를 거쳐 Racing에 진입했다. 테스트의 서버 낙사 판정선 아래에 P1을 놓았고 실제 경기의 첫 체크포인트 전 복귀 경로를 통과했다. 자동 계측은 정상 게임 시간으로 실행했고 장면 캡처 실행에서만 0.25배로 늦췄다.

| 정상 속도에서 낙하 넣은 뒤 | P1 호스트 | P2 및 P3 |
| --- | ---: | ---: |
| 첫 번째 소등 | 0.0562초 | 0.0562초 |
| 둘째 소등 | 0.3567초 | 0.3900초 |
| 셋째 소등 | 0.6676초 | 0.6676초 |
| 최종 표시 복원 | 0.8339초 | 0.8339초 |

호스트와 클라이언트 두 창에서 차량 메시 8개가 번갈아 숨겨졌다가 복구됐다. 카메라 대상과 충돌 모드는 모든 표본에서 같았고, 이전부터 숨겨진 프록시 메시가 나타나지 않았다. 검증은 P1 첫 체크포인트 이전 낙사다. 중간 체크포인트·원격 차주·서든데스는 이번 실행에서 직접 재현하지 않았다.

## 원격 차주 복귀 재검증

2026-11-27, Git `76be7dd` 및 최신 `main` `5a4006d` 기준. UE 5.8.4 `MWEditor Win64 Development`를 빌드했다. 로컬의 기존 아이템 소스 변경이 작업 트리와 빌드에 남아 있었다. 복귀 코드와 차량 설정에는 추가 변경이 없었다.

Cua Driver로 Snow 3인 리슨 서버 PIE를 시작했다. 각 창에서 직접 마우스로 트랙을 설치하고 `Racing`에 진입했다. P2(DOUG)와 P3(MAMMOTH)를 각각 서버 낙사 판정선보다 400cm 아래에 놓아 실제 경기의 첫 체크포인트 전 복귀를 일으켰다. 복귀 좌표와 점멸 상태는 서버와 차량 코드가 처리했다. 정상 속도로 수치를 기록했고, 별도의 P2 캡처만 0.25배로 실행했다.

| 대상 차량 | P1 호스트 | P2 창 | P3 창 |
| --- | --- | --- | --- |
| P2 원격 소유 차량 | 0.078초 소등, 0.838초 최종 복원 | 0.078초 소등, 0.838초 최종 복원 | 0.078초 소등, 0.865초 최종 복원 |
| P3 원격 소유 차량 | 0.114초 소등, 0.880초 최종 복원 | 0.114초 소등, 0.880초 최종 복원 | 0.114초 소등, 0.880초 최종 복원 |

시간은 낙사를 재현한 시점부터 호스트 월드의 게임 시각으로 계측했다. 모든 창에서 P2 차량의 메시 8개와 P3 차량의 메시 6개가 각각 세 번 점멸했다. 소등 표본의 차량 위치는 각 창의 최종 복귀 위치에서 5cm 이내였다. 최종 복귀 위치의 창 간 차이는 0.1cm 미만이었다. 카메라 대상·차체 충돌 모드는 전 구간에서 유지됐고, 기존 숨김 메시도 계속 숨겨졌다.

별도의 검토용 3인 PIE에서 다시 전원이 트랙을 설치하고 출발선 `Racing`까지 진입했다. 이 실행은 사용자가 직접 조작할 수 있게 정상 속도로 열어 뒀다. 중간 체크포인트 복귀, 서든데스와 별도 PC는 이번 재검증 범위 밖이다.
