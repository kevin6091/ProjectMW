# 롤러 접지 중 차체 표시 보정

UVCS cs:82 원본 기준. `fix/roller-pivot`의 UE 5.8.4 Editor 개발 빌드와 기존 `L_VehicleTrackIssues_Test` 3인 PIE로 확인했다.

## 선택한 방식

| 후보 | 검증 결과 |
| --- | --- |
| 롤러 외형 수정 | 원본 실루엣이 바뀌고 진입·이탈 좌우에 새 들뜸이 생겼다. |
| 주행 충돌 높이 수정 | 같은 좌표의 파고듦 수치는 줄었지만, 중앙 차량이 진입부에서 약 1.55m 더 높게 튀고 기존 주행 결과도 달라졌다. |
| 접지 중 차량 표시 위치 보정 | 롤러의 실제 표면을 조회해 차체와 바퀴의 표시 부모에만 월드 Z 오프셋을 적용한다. 충돌 루트와 네트워크 보정 부모 및 카메라는 기존 경로를 사용한다. |

## 수정 위치

- `Source/MW/Gameplay/Track/MWTrackRuntimeComponent.h/.cpp`에서 기존 롤러 모션에 연결된 메시를 캐시한다. 요청 좌표가 메시 범위에 있을 때 원본 에셋의 쿠킹된 삼각형을 직접 레이캐스트해 표면 높이를 조회한다. 원본 메시 참조와 현재 월드 변환을 재사용한다.
- `Source/MW/Gameplay/Vehicle/MWVehiclePawn.h/.cpp`에서 충돌이 없는 차량 외형 가지를 표시 전용 부모로 옮긴다. 기존 트리거 중첩으로 범위를 좁히고 실제 접지 검사를 재사용해 접지한 롤러를 고른다. 원래 바퀴 바닥과 표면 사이의 양수 차이 중 최댓값을 Z 표시 보정에 쓴다. 출시 차종이 바퀴 데이터를 생략한 경우 기존 박스 반높이를 사용한다.
- 카메라 부모인 `DrivePresentation`과 서버·예측 충돌 위치, 롤러 밀기 처리, 스키드 마크에 전달하는 바퀴 위치는 기존 경로를 사용한다. 접지를 잃거나 롤러 표면을 벗어나면 표시 오프셋이 0으로 돌아온다.
- `Source/MW/MW.Build.cs`에 원본 삼각형 레이캐스트를 위한 Chaos 비공개 의존성을 추가했다.

## 검증

- 최종 UE 5.8.4 Editor 빌드와 Cua Driver 3인 PIE를 완료했다. 최종 차체 계측 샘플에서 좌측 호스트와 중앙 원격 차량은 접지한 채 출구를 통과했고, 우측 조건은 cs:82와 같이 이탈했다.
- 중앙 원격 차량의 최대 월드 Z 표시 보정은 호스트 67.40cm, 소유자 창 68.06cm, 다른 원격 창 64.86cm였다. 각 창에서 실제 차체가 새 표시 부모에 연결됐고 카메라는 기존 `DrivePresentation`을 사용했다. 기록된 공중 프레임의 표시 보정과 모든 프레임의 X·Y 보정은 0cm였다.
- 우측 이탈 차량은 두 창에서만 관측됐다. 세 창의 접지와 표시 비교 표본은 좌측·중앙 주행에서 확보했다. 초기 빌드의 첫 중앙 원격 시도에서는 이탈했고, 같은 시작점의 재시험 및 최종 빌드의 중앙 주행은 통과했다. 여러 별도 실행의 궤적을 프레임 단위로 일치시킨 비교는 수행하지 않았다.
- 롤러 외형·외곽·충돌·카탈로그·BP·검증맵 7개 파일의 SHA-256이 UVCS cs:82 서버 원본과 일치했다. UVCS에 수정할 바이너리 에셋은 없다.

캡처와 프레임별 로그는 로컬 검증 폴더 `work/roller-pivot-audit/vehicle-presentation-fix`의 `final` 아래에 있다. 주행 샘플은 정지 상태에서 같은 가속 입력과 무조향 조건을 사용했다. 테스트 중 GPU 메모리 경고가 표시되어 프레임 성능 비교는 검증 범위에서 제외했다.
