# Make Way — TA 마일스톤 (Technical Art Workstream)

> 버전 v1.1 / 2026-10-22 · 기준: 기획 Draft v0.3, UE **5.8.3**  
> 작업 기간: D1~D20, 주 5일 × 4주 / 1일 6시간 · **책임자 C(클라이언트+TA)**  
> 이 문서는 **완료 시점·인수 조건·의존성**을 정의한다. 파일의 `Migration`은 별도 `03_TA_마이그레이션_실행계획.md` 참조.
> 조기 패키징/데이터 인수 변경 근거는 [클라이언트 개발 순서 및 설계 검토](05_클라이언트_개발순서_및_설계검토.md)에 기록한다. TA 48h와 일별 배분은 유지한다.

## 0. 시간과 우선순위

- C 전체 예산: **120인시** = TA 48시간 + 클라이언트 72시간. 아래 TA 작업은 **48시간을 넘기지 않는다**.
- TA 48시간 배분: 리소스 선별·이전 23h / 트랙 메타데이터·검증 툴 19h / 검증·최적화 증거 6h.
- 주차별 TA 상한: **W1 22h / W2 10h / W3 12h / W4 4h**. 남은 시간은 C의 아이템/위험 요소/HUD, 통합 및 QA에 사용.
- 추가 배경 맵, 차량 외형 2·3종, 범용 임포터의 전체 리팩터링은 마감일을 넘기지 않는다.
- 에셋 출처·라이선스가 검증되지 않은 추출물은 배포 빌드에 포함하지 않는다. 검증 전까지 플레이스홀더/사용 권리가 확인된 리소스로 개발한다.

## 3. 트랙 전달 계약 (TA → B/A)

1. B에게 전달할 각 조각: `PieceId`, `Mesh`, `EntrySocket`, `ExitSocket`, 연결 방향/폭/높이 허용 오차, 배치 Footprint, 위험 요소 Slot, 기본 체크포인트 정보.
2. 명칭/데이터 구조는 D2에 합의하고 **D3 이후 변경 시 B의 승인 필요**. 신규 조각은 기존 데이터 계약을 변경하지 않는 방향으로 추가.
3. A는 차량의 충돌 채널·접지 조건·복귀 가능 공간을 검토한다. C는 '콜리전이 존재한다'와 '주행 가능한 콜리전이다'를 구분한다.
4. 정상 트랙과 실패 트랙(소켓 누락/반대 방향/콜리전 누락)을 **각 1개 이상** 재현용으로 보관한다.
5. 자동 생성이 어려운 연결점과 안전 스폰 지점은 아티스트가 수동 확인하고 Validator로 누락을 검사한다. 메시 형상만으로 무조건 자동 판단한다고 주장하지 않는다.

### TA 수정 승인 체크리스트

- [ ] 주행 규격(전방 축/피벗/센티미터 단위) 일치
- [ ] 입구·출구 소켓과 연결 변환 유효
- [ ] 주행 Surface Collision이 실제 차량에 정상 반응
- [ ] 위험 요소 슬롯이 주행 폭·스폰을 침범하지 않음
- [ ] 필수 메시·머티리얼·텍스처 참조 정상
- [ ] 네트워크 3인 배치·주행 테스트에서 시각-충돌 불일치 없음
- [ ] 라이선스/출처와 공개 빌드 사용 여부 기록

## 4. 불변 우선순위 및 중단 규칙

- **P0:** 차량 1/규격을 만족하는 트랙 3종부터 전달. 경사가 D3에 실패하면 평면 변형으로 대체한다. D14까지 트랙 총 5종 조건부 목표, D15 동결.
- **P1:** Validator 자동수정(안전한 일부 항목에 한함), 위험 요소/보조 요소 메타데이터, 머티리얼 정리.
- **P2:** 자동 텍스처 의미 분류 고도화, 추가 차량·맵, 화려한 전용 툴 UI.
- **D5 실패:** 새 에셋 추출 중단 → 3종 플레이스홀더의 연결/콜리전 오류 해결.
- **D10 매치 실패:** TA 작업 W3 잔여량을 줄이고 C의 게임플레이 통합 시간을 우선 확보.
- **D15 이후:** 에셋 대체도 회귀 테스트 없이는 금지. 새 기능·새 배경 금지.

## 5. 포트폴리오에 남길 수치와 증거

| 항목 | 수집 방법 | 피해야 할 주장 |
|---|---|---|
| 자동 검증 속도 | 동일한 에셋 N종을 수동/툴로 검사한 소요 시간 | 임의의 '80% 절감' 등 측정 없는 수치 |
| 검출 정확성 | 의도적으로 잘못 만든 소켓/참조/콜리전 사례별 탐지 여부 | 트랙 안전성 전체를 완전 자동 검증했다고 주장 |
| 리소스 도입 효율 | 원본별 준비 시작/UE5 플레이 가능 시점 기록 | 추출·임포트 시간과 게임플레이 구현 시간을 혼동 |
| 성능 | 동일 장면·빌드·PC에서 GPU/CPU/메모리 비교 | FPS 한 번 측정만으로 최적화 주장 |
| 실사용 증거 | B의 TrackManager가 이식된 조각을 사용한 영상 | 테스트 전시용 툴을 실프로덕션 적용으로 포장 |

## 6. 의존성 및 책임 경계

- **C → B (D2~D3):** 트랙 소켓 규격/정상 메시. B는 서버 스냅·충돌·소유권·배치 순서를 책임진다.
- **C → A (D2~D3):** 자동차 메시/트랙 충돌 테스트. A는 차량 Movement, 카메라, 네트워크 제어를 책임진다.
- **B → C (D6~D8):** 확정된 위험 요소 Slot 설치 API. C는 위험 요소의 판정·효과·에셋을 담당한다.
- **A → C (D3 시험/D5 계약/D7~D8 통합):** 속도 변경/넉백/복귀 API. C는 내부 이동 변수를 직접 수정하지 않는다.
- **Editor ↔ Runtime:** TA Editor 도구는 Runtime 게임 코드에서 직접 참조하지 않는다. Runtime DataAsset의 형식만 공유한다.

## 7. 기본 정의와 미확정 항목

- AssetFlow는 기존에 개발 중인 도구로 **언급되었지만 이번 문서 작성 시 실제 코드/브랜치를 검사하지 않았다**. 지원 기능·완성도는 D1 확인 항목이다.
- Unity/기타 원본에서 추출한 콘텐츠의 패키징 권한은 미확인 상태. 사용 권한이 확보된 에셋과 플레이스홀더로 먼저 진행한다.
- `TrackPieceDefinition` 및 각 C++ 클래스 이름은 **설계상 제안명**이며 실제 리포지토리 명칭이 아니다.
- 이 마일스톤은 본인의 TA 전담 48h만 포함한다. 전체 팀의 게임 개발 일정은 클라이언트 마일스톤이 기준이다.
