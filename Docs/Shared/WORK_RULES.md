# 공용 작업 규칙

이 문서는 모든 ProjectMW 작업의 선행 필독이다. 분야 판정과 전체 필독 경로는 [작업 분류 스킬](../../.agents/skills/mw-task-routing/SKILL.md)을 따른다.

## 문서 역할

- 이 폴더 직속 문서: 프로젝트 공용 규칙과 기획.
- [3인 팀 Git 공통 규칙](GIT_COLLABORATION_GUIDE.md): 모든 분야 필독. 브랜치·독립 리뷰·순차 병합·LFS/에셋 예약·충돌/복구의 단일 기준이다.
- [TA 공유 문서](TA/WORK_RULES.md): 에셋 규격·TA 도구·마이그레이션·TA 일정.
- [개발 공유 문서](Client,Server/WORK_RULES.md): Client/Server 계약·개발명세·통합 일정.
- `Docs/Art`, `Docs/Engineering/Client`, `Docs/Engineering/Server`: 분야별 작업 지침과 이후 추가되는 분야 문서.

## 필수 운영

1. 작업 분야에 해당하는 문서를 수정 전에 읽는다. 복합 작업은 여러 분야를 함께 적용한다.
2. 사용자가 만든 폴더 구분과 명칭을 유지한다. 문서를 이동할 때는 참조 링크와 필독 경로도 함께 고친다.
3. 현재 기획·명세·마일스톤을 기준으로 범위와 완료 조건을 확인한다. 기획 변경을 요청받았다면 변경 이유와 영향도 관련 문서에 반영한다.
4. 구현 사실, 제안, 미검증 상태를 구분한다. 읽지 않은 문서를 필독 완료로, 실행하지 않은 빌드/테스트를 성공으로 기록하지 않는다.
5. 공용 데이터/API/바이너리 에셋의 변경은 소비 분야와 담당 영역을 확인하고 함께 검증한다. 과거 문서의 제안 클래스명과 실제 소스 이름은 구분한다.
6. Git 관련 작업은 위 공통 규칙을 적용한다. 다른 문서의 과거 브랜치 예시·일일 통합 표현을 무리뷰 main 반영이나 바이너리 자동 병합 허가로 해석하지 않는다.
7. 완료 보고에는 적용 분야, 변경 사항, 검증 결과, 미해결 항목을 적는다. 작업 분류 확인을 위한 별도 승인 절차는 만들지 않는다.

상위 지침과 현재 사용자의 명시적 요청이 우선한다. 문서 상호 충돌은 근거를 확인해 적용 기준을 설명하고, 판단할 수 없는 사항만 확인한다.
