# Client · Server 개발 공유 규칙

개발 작업은 이 폴더에 있는 개발명세·마일스톤·작업 순서를 선행 확인한다. 기존 문서명이 클라이언트여도 Listen Server 권한과 복제 계약을 함께 다룬다.

- 서버는 게임 규칙·배치·점수·아이템 결과를 확정하고 Client는 입력·요청·표시 및 채택한 이동 솔루션의 예측을 담당한다. 단일 실행 파일 안에 있어도 이 책임을 구분한다.
- 공용 상태·RPC·ID·리비전·Phase·객체 수명을 바꾸면 송신자와 수신자 모두의 코드를 확인한다. Client/Server 중 필요한 분야를 함께 적용한다.
- 트랙 정의·콜리전·소켓·설치 슬롯·체크포인트/복귀 데이터를 바꾸면 TA 공유 문서와 Art 지침도 읽는다.
- 브랜치·에셋 예약·PR·main 반영은 [Git 공통 규칙](../GIT_COLLABORATION_GUIDE.md)을 단일 기준으로 따른다. 담당 영역 표는 장기 개인 브랜치나 독점 수정 권한을 의미하지 않는다.
- 실제 Runtime 모듈은 `Source/MW`다. Editor 기능은 필요 시 별도 Editor 모듈에 두고 패키지 의존성을 검증한다.
- 3인 Listen Server가 우선 검증 범위다. 2/4인·Dedicated Server·중도 참가 지원을 구현/검증 없이 완료로 표시하지 않는다.
- 정상 요청뿐 아니라 해당 변경과 관련된 중복·오래된 상태·권한·시간초과·이탈 경로를 검증한다. 테스트 규모는 실제 변경 영향에 맞춘다.

일별 일정의 단일 원본은 [개발 마일스톤](02_클라이언트_마일스톤_4주.md), 시스템 간 계약은 [개발명세](MakeWay_클라이언트_개발명세서_v1.0.md), 큰 순서와 설계 근거는 [개발 순서 및 설계 검토](05_클라이언트_개발순서_및_설계검토.md)를 사용한다. [공용 데이터 이식](06_공용_데이터_이식.md)은 현재 기반 구현과 로딩 계약, [차량 입력·이동·효과 상세 설계](07_차량_입력_이동_효과_설계.md)는 채택한 차량 내부 구조·키/입력 의미·효과 수명·시각 자료의 원본이다. 설계 채택과 Runtime 구현/검증 완료를 구분한다. 기존 코드를 이전할 요청이 생기면 실제 원본과 재사용 범위를 확인하고 별도 계획을 수립한다.
