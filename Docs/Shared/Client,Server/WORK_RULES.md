# Client · Server 개발 공유 규칙

현재 연결 경계·API·프로젝트 연동 기준은 [독립 연결 모듈](15_독립_연결모듈_API와_프로젝트_연동.md)이다. 2026-11-02 사용자 지시로 EOS·세션을 MWConnection Runtime 플러그인에 격리하고, 프로젝트의 단일 소비자를 MWGameInstance로 변경했다. 기존 MWMultiplayerSubsystem은 Blueprint 호환용 전달 계층만 남긴다.

2026-11-02 채택한 역할 분리·시작 흐름의 정본은 [로비·게임플레이 분리와 차량 선택 전환 계약](16_로비_게임플레이_분리와_차량선택_전환_계약.md)이다. GameMode·GameState·PlayerController는 로비/게임플레이로 분리하고 PlayerState는 공용으로 사용한다. `GameStart → VehicleSelection → 시작 대상 전원의 서버 승인 선택 확정 → Traveling → 테마 이동`을 구현 목표로 한다. 차량 선택은 L_Title에서 마치고, UI 없는 초기 버전도 각 소유 클라이언트가 기본 ID를 RPC로 제출한다. 이는 설계 채택이며 기존 즉시 이동 구현·14~15번 문서의 과거 검증 완료를 새 흐름의 구현 완료로 해석하지 않는다. 연결 API와 기존 검증 범위는 계속 15번 문서를 따른다.

[게임플레이 진행 상태와 Phase 단일 전환 설계](18_게임플레이_진행상태와_Phase_단일전환_설계.md)는 2026-11-12의 현재 브랜치를 기준으로 GameState/PlayerState 경기 기록, 공통 진행 검사와 EnterPhase, 트랙 완료·실패 보고, 출발 준비·결과·코스 확장·재경기를 구체화한 구현 전 설계다. Runtime 구현 완료를 뜻하지 않으며, 사용자 요청 전에는 소스 구현에 착수하지 않는다. 로비 차량 선택과 연결 API는 계속 16번·15번 계약을 따른다.

개발 작업은 이 폴더에 있는 개발명세·마일스톤·작업 순서를 선행 확인한다. 기존 문서명이 클라이언트여도 Listen Server 권한과 복제 계약을 함께 다룬다.

- 서버는 게임 규칙·배치·점수·아이템 결과를 확정하고 Client는 입력·요청·표시 및 채택한 이동 솔루션의 예측을 담당한다. 단일 실행 파일 안에 있어도 이 책임을 구분한다.
- 공용 상태·RPC·ID·리비전·Phase·객체 수명을 바꾸면 송신자와 수신자 모두의 코드를 확인한다. Client/Server 중 필요한 분야를 함께 적용한다.
- 트랙 정의·콜리전·소켓·설치 슬롯·체크포인트/복귀 데이터를 바꾸면 TA 공유 문서와 Art 지침도 읽는다.
- 브랜치·에셋 예약·PR·main 반영은 [Git 공통 규칙](../GIT_COLLABORATION_GUIDE.md)을 단일 기준으로 따른다. 담당 영역 표는 장기 개인 브랜치나 독점 수정 권한을 의미하지 않는다.
- 게임 Runtime 모듈은 `Source/MW`, 독립 연결 Runtime 모듈은 `Plugins/MWConnection`이다. Editor 기능은 필요 시 별도 Editor 모듈에 두고 패키지 의존성을 검증한다.
- 3인 Listen Server가 우선 검증 범위다. 2/4인·Dedicated Server·중도 참가 지원을 구현/검증 없이 완료로 표시하지 않는다.
- 정상 요청뿐 아니라 해당 변경과 관련된 중복·오래된 상태·권한·시간초과·이탈 경로를 검증한다. 테스트 규모는 실제 변경 영향에 맞춘다.

일별 일정의 단일 원본은 [개발 마일스톤](02_클라이언트_마일스톤_4주.md), 시스템 간 계약은 [개발명세](MakeWay_클라이언트_개발명세서_v1.0.md), 큰 순서와 설계 근거는 [개발 순서 및 설계 검토](05_클라이언트_개발순서_및_설계검토.md)를 사용한다. [공용 데이터 이식](06_공용_데이터_이식.md)은 현재 기반 구현과 로딩 계약, [차량 입력·이동·효과 상세 설계](07_차량_입력_이동_효과_설계.md)는 채택한 차량 내부 구조·키/입력 의미·효과 수명·시각 자료의 원본이다. 설계 채택과 Runtime 구현/검증 완료를 구분한다. 기존 코드를 이전할 요청이 생기면 실제 원본과 재사용 범위를 확인하고 별도 계획을 수립한다.

[리슨 서버 구조와 Gameplay Framework 이해](08_리슨서버_구조와_Gameplay_Framework.md)는 GameMode·GameState·PlayerState의 역할, 서버/클라이언트 요청·복제 흐름과 ACharacter 기반 차량을 설명한다. 2026-10-26 사용자 지시에 따라 차량은 ACharacter + CharacterMovement 확장 방향으로 계획한다. 세부 이동·충돌·보정은 초기 검증 대상이며, 과거 Chaos Vehicles 우선 검토를 현재 구현 지시로 사용하지 않는다.

[타이틀부터 게임플레이까지의 마일스톤](09_타이틀부터_게임플레이까지_마일스톤.md)은 경기 생성·방 설정·검색/참가·여러 독립 호스트·로비·건설·출발의 기능 인수 순서다. 무료 EOS를 인터넷 경로로 시험하고 유료 구독을 필수 전제로 두지 않는다. LAN 검증과 인터넷 완료를 구분하며 일별 시간 재배분은 02 문서에서 관리한다.

[AssetManager 맵 테마 기반 방 생성 구현 가이드](10_AssetManager_맵테마_기반_방생성_구현가이드.md)는 2026-10-28 단계의 실습 기록이다. 맵 테마 제작·조회 계약의 원본은 계속 06 문서 6.3절이다. 기존 Subsystem을 계속 확장하고 새 Subsystem을 만들지 말라는 이전 지침은 사용자의 독립 모듈 구현 지시로 대체됐다. 현재 연결 기능은 MWConnection 공개 API로만 접근하고 MWMultiplayerSubsystem에 기능을 추가하지 않는다. 게임 카탈로그·테마 경로 표를 플러그인에 중복 생성하지 않는다. 이전 코드 예제로 현재 Source를 덮어쓰지 않는다.
