# 플레이어 커서 공유

2026-11-05 / Client + Server / `feature/shared-cursor`

기준은 `main@8cbeec4`다. 차량 선택에서 참가자의 마우스 위치를 서버를 거쳐 공유하며, 같은 전송 계층을 트랙 선택의 월드 좌표에도 사용할 수 있다. 실제 트랙 선택 화면은 main에 없으므로 이번에 새로 만들지 않는다.

## 책임과 호출 경로

```text
서버 LobbyGameMode: 시작 대상의 차량 선택 커서 스트림 열기
  → PlayerState.CursorComponent의 스트림 정보 복제

로컬 LobbyHUD.Tick
  → VehicleSelectionWidget.SampleSharedCursor
  → MWCursorProjection: 현재 마우스 → UI 레이어의 정규화 좌표
  → 자기 PlayerState.CursorComponent.SubmitLocalCursor
  → ServerSubmitCursor (Unreliable, 최대 20Hz)
  → 소유 연결·스트림·순서·좌표·처리량 검사
  → 해당 PlayerState의 최신 커서 상태 복제

수신 LobbyHUD.Tick
  → 다른 PlayerState들의 현재 커서 상태 조회
  → VehicleSelectionWidget.ProjectSharedCursor
  → MWCursorProjection: 자기 선택판 → 화면 좌표
  → MWRemoteCursorOverlay: 보간 및 표시
```

| 코드 | 책임 | 의존하지 않는 것 |
|---|---|---|
| `Player/Cursor/MWSharedCursorTypes.h` | 화면 컨텍스트, 스트림 ID, 좌표계, 위치, 표시 여부 | 차량 정의·트랙 후보·UMG |
| `Player/Cursor/MWPlayerCursorComponent` | 소유자의 RPC 전송, 서버 검사, 복제, heartbeat/만료 | 화면 클래스·카메라·Phase enum·선택 결과 |
| `UI/Cursor/MWCursorProjection` | UI 표면의 좌표 수집과 화면 투영 | 네트워크·PlayerState·차량 선택 승인 |
| `UI/Cursor/MWRemoteCursorOverlay` | 화면이 공급한 커서 위젯의 크기·끝점 정렬, 위치 보간·표시·제거 | 서버·PlayerArray·차량/트랙·특정 커서 에셋 |
| `MWVehicleSelectionWidget` | 기존 CursorLayer, main 커서 위젯 클래스와 참가자 표시 데이터를 공통 기능에 제공 | RPC·서버 상태 변경 |
| `MWLobbyHUD` | 화면 수명, 샘플 수집과 전송 연결, 수신 상태와 표시 연결 | 서버 선택 확정 |
| `MWLobbyGameMode` | 시작 대상 참가자에게 차량 선택 스트림 허용/종료 | 마우스 읽기·표시 좌표 계산 |

`MWPlayerCursorComponent`는 공용 `MWPlayerState`의 기본 서브오브젝트다. 소유 PlayerState의 Owner인 PlayerController를 통해 Server RPC의 owning connection을 사용한다. 다른 플레이어 ID를 RPC 인자로 받지 않는다. LobbyPlayerController/GameplayPlayerController에 동일한 RPC를 각각 복사할 필요가 없다.

## 서버가 허용하는 스트림

`OpenStreamForServer(Context, Space)`는 서버 권한에서만 동작한다. 서버가 차량 선택을 시작할 때 고정된 시작 대상의 스트림을 연다. 종료·실패·Traveling 진입 전에 닫는다. 클라이언트는 복제된 스트림을 확인한 뒤 그 스트림 ID로만 샘플을 제출할 수 있다.

열 때마다 새로운 StreamId를 발급한다. 스트림 안에서는 증가하는 Sequence를 검사한다. 이전 화면의 패킷, 중복·역순 패킷, 닫힌 스트림의 패킷은 상태를 바꾸지 않는다. 위젯 재생성 시 전송 순서번호는 PlayerState 컴포넌트에 남아 있으므로 같은 스트림에서 역행하지 않는다.

이 ID들은 커서 표시 스트림에만 사용한다. 차량 선택 확정 상태에 별도 `bConfirmed`나 선택 요청 리비전을 추가하지 않는다. 차량 선택의 원본은 기존 `VehicleAssetID`다.

## 좌표 계약

`NormalizedWidget`은 해당 화면의 기준 UI 레이어에서 `X,Y ∈ [0,1]`, `Z=0`이다. 차량 선택은 기존 CursorLayer를 기준으로 한다. 화면 픽셀이나 OS 바탕화면 좌표를 복제하지 않는다.

- 일반 화면 UI에서는 Slate의 실제 레이어 Geometry와 Viewport Geometry로 변환한다.
- 평면 World UI에서는 마우스 광선과 WidgetComponent 평면을 교차시키고, 실제 DrawSize·Pivot·Transform과 레이어 Geometry를 이용한다.
- 수신 World UI는 같은 논리 위치를 자기 Widget 표면의 월드 위치로 바꾸고 자기 카메라에 투영한다.
- 원격 표시는 별도 Viewport 오버레이에 그린다. World UI 배경/기둥의 깊이 검사에 가려지지 않으며 클릭을 가로채지 않는다.
- 원통형 WidgetComponent는 지원하지 않는다. 표면/Geometry가 준비되지 않았거나 화면·창 밖이면 숨김 상태다.
- 정규화 좌표는 동일한 논리 레이아웃의 크기·배율 차이에 대응한다. 서로 다른 카드 순서·전혀 다른 레이아웃의 의미상 동일 카드까지 자동 매핑하는 계약은 아니다.

`World`는 월드 cm이고 각 축 절댓값의 상한은 1,000,000cm다. 트랙 선택은 서버가 World 스트림을 열고 화면이 계산한 월드 위치를 동일한 SubmitLocalCursor로 제출하면 된다.

위치는 FVector의 정밀도를 유지한다. 정규화 [0,1] 좌표에 1cm/0.01 단위 NetQuantize를 직접 사용해 커서가 큰 간격으로 움직이는 것을 피한다. 현재 2~4인 표시용이며 대역폭 수치를 측정 완료로 보장하지 않는다.

## 전송·복제·만료

- 클라이언트 제출은 최대 20Hz다. 첫 숨김은 즉시 보낼 수 있다.
- 정지/숨김 상태도 화면이 열려 있는 동안 heartbeat로 전송한다. 마지막 이동/숨김 RPC 한 개의 유실에 의존하지 않는다.
- 서버는 별도로 최대 30개의 burst 예산과 초당 30개 회복을 적용한다.
- 유한 좌표·좌표계 범위, 현재 서버 스트림, 증가하는 순서번호를 검사한다.
- 표시 중 마지막 유효 샘플부터 0.75초 동안 갱신이 없으면 서버가 숨긴다. 같은 위치의 heartbeat도 만료를 연장한다.
- 같은 위치의 heartbeat는 ForceNetUpdate를 반복하지 않는다.
- 커서 상태는 별도로 복제하며 `OnPlayerStateChanged`와 차량 목록 Refresh를 발생시키지 않는다.
- 공통 컴포넌트는 Tick하지 않는다. 차량 선택 HUD만 화면이 열려 있는 동안 Tick하며, 포인터별 화면 위치를 보간한다.

20Hz는 제출 상한이며 모든 클라이언트에 정확히 20회씩 전달된다는 보장은 아니다. 실제 전달 주기는 엔진 복제와 연결 상태의 영향을 받는다.

## 표시 정책

자기 커서는 기존 소프트웨어/OS 커서를 사용한다. 기존 클릭 위치의 원형 고정 표시와 차량 카드의 확정 마커를 유지한다.

2026-11-06 사용자 요청으로 원격 커서의 `+ P번호 이름` 텍스트 표시를 교체했다. 차량 선택 화면의 LocalPlayerCursor와 같은 Blueprint 클래스로 `MWVehiclePlayerMarkerWidget`을 생성해 main의 원형·화살표 모양을 재사용한다. 색상·P번호·이름·확정 상태는 기존 ParticipantViews를 SetPresentation에 전달하며, 이미지 색상은 기존 PlayerTint 경로로 적용한다. 표시 크기는 자기 소프트웨어 커서와 같은 Designer 슬롯 크기를 사용하고, MWGetPointerHotspot으로 구한 화살표 끝을 공유 좌표에 맞춘다. 원격 표시에는 로컬 플레이어 표시를 켜지 않는다.

오버레이는 화면이 공급한 일반 UUserWidget과 디자인 크기·표시 크기·끝점 위치만 받는다. 특정 차량 마커 클래스를 참조하거나 커서 에셋을 직접 로드하지 않는다. 이후 트랙 화면도 선택한 커서 위젯을 같은 표시 계층에 공급할 수 있다. 신규 이미지·커서 BP·재질은 만들지 않는다.

차량을 확정해 선택 입력이 잠기거나 서버 응답을 기다리는 동안에도 커서 공유는 계속된다. 커서의 위치는 Hover 차량 확정, VehicleAssetID 변경, 전원 완료, 맵 이동의 판정에 사용하지 않는다. Preview의 가상 참가자는 실제 네트워크 커서로 전송하지 않는다.

## 수명과 트랙 연결

서버 화면 전환 시 스트림을 닫고, 클라이언트는 HUD 종료 시 숨김을 제출하고 오버레이를 제거한다. 참가자가 나가거나 상태가 숨겨지면 그 표시·보간 캐시를 제거한다. 컴포넌트 EndPlay는 만료 타이머를 제거한다. 커서 상태는 PlayerState.CopyProperties로 맵 간 복사하지 않는다.

후속 트랙 선택 연결 순서는 다음과 같다.

1. 서버의 트랙 선택 시작/종료에서 각 참가자의 CursorComponent에 별도 컨텍스트와 `EMWCursorSpace::World` 스트림을 열고 닫는다.
2. 트랙 화면이 마우스의 월드 위치를 구해 `SubmitLocalCursor`에 전달한다. 전송/서버 만료/복제 코드를 다시 만들지 않는다.
3. 수신 화면이 World 위치를 자기 카메라에 투영하고, 재사용할 커서 위젯과 크기·끝점 정보와 함께 `MWRemoteCursorOverlay`에 넘긴다.
4. 트랙 선택 세션/참가자 검사는 트랙 진행 코드가 스트림을 허용할 때 수행한다. 기존 테스트 브랜치의 Construction 전용 Cursor 상태와 타이머는 함께 쓰지 않는다.

## 검증 범위

2026-11-05의 텍스트 커서 구현 시점에 UE 5.8.4 / Win64 Development에서 MWEditor와 MW 빌드 통과. `MW.Cursor` 자동화 3개 통과:

- StreamValidation: 스트림 권한·컨텍스트, 순서·세대, 잘못된 좌표, 종료/재진입, 처리량 제한, 맵 인계 제외, World 좌표 재사용.
- ExpiryAndHeartbeat: 실제 후속 엔진 프레임의 TimerManager에서 정지 heartbeat와 전송 중단 만료.
- WorldWidgetProjection: 엔진의 실제 GetLocalHitLocation과 대조한 회전·Pivot·스케일의 왕복 변환.

결과: `Saved/Codex/SharedCursor/Automation/index.json`.

LocalIP에서 같은 에디터의 3개 PIE 월드가 실제 로비에 접속한 것까지 확인했다. 자동 진행에서 호스트 Ready만 반영되고 원격 Ready는 반영되지 않아 차량 선택 단계까지의 통합 검증을 마치지 못했다. 원인이 검증 호출 문맥인지 기존 동작인지 확정하지 않았다. 이후 사용자의 검증 중단 지시에 따라 추가 실행을 중단했다. 실제 커서 RPC의 클라이언트 간 동기화·원격 포인터 화면·OS 마우스·WAN·Cook/패키지는 검증 완료로 기록하지 않는다.

2026-11-06의 main 커서 모양 재사용 변경은 검증 중단 지시를 유지해 빌드·자동화·PIE를 실행하지 않았다. 위 빌드·자동화 결과를 이 후속 변경의 검증 결과로 해석하지 않는다.

### 후속 스크린샷 요청 — 2026-11-06

이후 사용자가 스크린샷 촬영을 요청해 해당 범위의 Editor 빌드와 실제 RHI 표시를 실행했다. 캡처 중 오버레이 루트가 NativeConstruct에서 늦게 생성되어 Slate에는 빈 Spacer가 남는 문제를 확인했다. 루트 생성 시점을 RebuildWidget의 Super 호출 전으로 옮겼다.

`L_VehicleSelection_UI_Dev`의 실제 차량 선택 UI에서 기존 커서 BP를 이용한 빨강·파랑 원격 커서 두 개와 초록 로컬 커서를 표시했다. 촬영용 로컬 참가자 데이터를 사용했으며, 네트워크 패킷 수신 성공을 입증하는 화면은 아니다. 임시 촬영용 C++ 코드는 캡처 후 제거했다. 커서 BP·텍스처·맵 에셋은 새로 제작하거나 저장하지 않았다.
