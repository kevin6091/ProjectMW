## 1. 게임 개요

### 1.1 핵심 콘셉트

2\~4명의 플레이어가 라운드마다 직접 트랙을 이어 붙이고, 자신들이 만든 코스에서 아이템과 차량 충돌을 활용해 경쟁하는 파티 레이싱 게임.

레이스가 종료되면 기존 트랙을 보존한 채 새로운 조각을 추가한다. 같은 코스를 점점 길고 복잡하게 확장하며 목표 점수에 먼저 도달하기 위해 경쟁한다.

### 1.2 프로젝트의 차별화

1. 공용 탑다운 카메라 대신 플레이어별 3인칭 카메라 제공
2. 예측 가능한 아케이드 차량 조작 및 카메라 안정화
3. 마우스 기반 트랙 선택·소켓 자동 정렬·배치 UI
4. 여러 플레이어가 동시에 트랙을 선택하고 배치를 요청할 수 있는 건설 시스템
5. 보유 아이템 및 레이스 상태의 시각적 전달 개선
6. 선두와 일정 거리 이상 벌어진 플레이어의 자동 탈락 및 체크포인트 복귀
7. 트랙 에셋 검증과 배치용 메타데이터 설정을 자동화하는 TA 툴 제작

### 1.3 목표 경험

- 직접 배치한 트랙이 다음 레이스의 변수로 작용한다.
- 경쟁자를 방해하면서도 자신의 주행 실력으로 역전할 수 있다.
- 플레이어가 건설과 레이싱 사이를 빠르게 전환한다.
- 복잡한 조작을 외우지 않고도 트랙을 만들 수 있다.

## 2. 콘텐츠 구성

### 2.1 차량

**이번 일정: 외형 1종 / 주행 모델 1종. 외형 3종은 후속 확장 후보.**

- 스포츠 카트
- 소형 해치백
- 오프로드 스타일 차량

차량 3종은 우선 외형만 다르게 제작한다. 가속력, 최고 속도, 조향 능력은 동일하게 유지한다.

차량마다 고유한 물리 특성을 만드는 기능은 제외한다. 조작감 하나를 제대로 완성하고 검증하는 편이 더 중요하다.

### 2.2 트랙 조각 (Track Pieces)

트랙 조각은 차량이 실제로 달리는 **도로 표면과 연결 지점**을 구성하는 요소다.

원작에 등장하는 트랙 유형을 바탕으로 일반 트랙, 지형 변화 트랙, 특수 기믹 트랙으로 나눈다.

#### 2.2.1 일반 트랙

| 종류     | 기능                | 개발 우선순위 |
| ------ | ----------------- | ------- |
| 직선     | 고속 주행 구간 구성       | P0      |
| 커브     | 방향전환              | P0      |
| S자 커브  | 좌우 연속 조향          | P1      |
| 나선형 커브 | 연속적으로 회전하는 복잡한 경로 | P2      |

원작에는 직선과 커브, 나선형 구간이 확인된다. 다만 짧은·긴 직선, S자 등은 구현 편의를 위한 세부 분류이며 원작에서 정확히 독립된 아이템으로 등장하는지는 추가 확인이 필요하다.

#### 2.2.2 지형 변화 트랙

| 종류            | 기능                    | 개발 우선순위 |
| ------------- | --------------------- | ------- |
| 경사 트랙 / 점프 램프 | 높이 변화 및 점프            | P0      |
| 끊어진 도로        | 차량이 틈을 뛰어넘어야 하는 구간    | P1      |
| 좁은 다리         | 추락 위험이 높은 통행 구간       | P1      |
| 움직이는 다리       | 시간에 따라 통행 조건이 달라지는 구간 | P2      |

원작 리뷰에서 점프 구간과 움직이는 다리가 확인된다. 좁은 다리는 이번 제작을 위한 세부 변형 후보로 취급한다.

#### 2.2.3 특수 기믹 트랙

| 종류                     | 기능                      | 개발 우선순위 |
| ---------------------- | ----------------------- | ------- |
| 시소(Seesaw)             | 차량의 무게나 상태에 따라 기울어지는 도로 | P2      |
| 기차 건널목(Train Crossing) | 움직이는 기차를 피하면서 통과하는 구간   | P2      |
| 루프(Loop)               | 차량이 수직 회전 구간을 통과        | P3      |
| 코르크스크루(Corkscrew)      | 도로 자체가 입체적으로 회전         | P3      |
| 회전교차로                  | 회전교차로                   |         |

위 네 종류는 원작 공식 소개에서 확인되는 트랙 유형이다.

**D5 초기 목표는 규격을 만족하는 트랙 3종, D14 조건부 목표는 기본 트랙 총 5종이다.** 7종과 특수 기믹은 이번 필수 일정에서 제외한다. 경사/점프는 차량의 원격 접지·착지 검증을 통과할 때 포함하며, 실패하면 평면 변형으로 대체한다.

루프와 코르크스크루는 원작의 주요 요소지만 4주 프로젝트에서는 구현을 권장하지 않는다. 3인칭 시점의 차량 접지, 수직 회전, 네트워크 물리 보정 문제까지 함께 발생하기 때문이다.

#### 2.2.4 트랙 공통 데이터

모든 트랙에는 다음 정보를 정의한다.

- 입구·출구 연결 소켓
- 트랙 주행 중심선
- 트랙 폭과 연결 규격
- 콜리전
- 위험 요소 설치 가능 슬롯
- 체크포인트 판정 구역
- 배치 가능 여부와 간섭 검사
- 필요한 경우 커브 예고 데이터

P0 좌우 커브는 별도 데이터 후보로 제공한다. 단일 In/Out 소켓에 자동 정렬하며 임의 회전·런타임 미러링은 제외한다. 메시 공유 여부는 임포트/주행 검증 후 결정한다.

### 2.3 트랙 위험 요소 (Track Hazards)

트랙 위험 요소는 플레이어가 도로 위에 설치해 상대 차량의 이동을 방해하는 요소다.

**트랙 조각과 별개의 카테고리**로 관리하며, 위험 요소가 설치되었다고 트랙 조각 수가 증가하지 않는다.

#### 2.3.1 첨부 레퍼런스 기준 원작 위험 요소 7종

| 종류        | 효과 및 기믹               | 개발 우선순위 |
| --------- | --------------------- | ------- |
| 바리게이트     | 바리게이트                 |         |
| 범퍼        | 고정된 충돌체로 차량을 밀어냄      | P0      |
| 사이드 팬     | 옆 방향 바람으로 차량 주행 방해    | P1      |
| 바닥 환풍기    | 위쪽으로 힘을 가해 차량 거동 변화   | P1      |
| 흔들리는 큰 포대 | 진자처럼 움직여 차량과 충돌       | P2      |
| 발사대       | 차량이 밟으면 튕겨 나가는 판형 기믹  | P0\~P1  |
| 움직이는 범퍼   | 일정한 경로를 이동하며 차량을 방해   | P1      |
| 롤러 다리     | 롤러 또는 움직이는 발판을 건너는 기믹 | P2      |

위 명칭과 외형은 첨부한 Make Way 실제 게임 캡처를 기준으로 한다. 구체적인 힘과 충돌 수치는 직접 플레이해 확인한 후 결정한다.



#### 2.3.3 배치 제약

- 트랙의 설치 가능 슬롯에만 배치한다.
- 차량 스폰 지점과 체크포인트 복귀 공간을 침범하지 않는다.
- 출입구 전체를 차단하는 배치는 거부한다.
- 이미 설치된 위험 요소와의 중첩을 검사한다.
- 서버에서 최종 배치 유효성을 검증한다.

### 2.4 트랙 보조 요소 (Track Utilities)

보조 요소는 단순히 플레이어를 방해하기보다는 이동이나 아이템 획득 등의 기능을 제공한다.

| 종류     | 기능                   | 개발 우선순위 |
| ------ | -------------------- | ------- |
| 가속 패드  | 통과한 차량의 속도를 일시적으로 증가 | P0      |
| 아이템 박스 | 아이템 1개 획득            | P0      |
| 점프대    | 차량이 공중으로 점프          | P1      |
| 불도저    | 배치 요소 삭제 기능으로 활용 검토  | 보류      |

불도저는 원작의 위험 요소 목록에도 등장한다. 이번 초안에서 제안한 '배치 요소 삭제' 기능이 원작과 동일하다고 확인된 것은 아니므로, 독자적인 건설 도구로 만들 경우 해당 사실을 별도로 표시한다.

점프대는 트랙의 일부로 만들지, 별도 설치 요소로 만들지 결정해야 한다.

**이번 일정: 아이템 박스·가속 패드 2종. 추가 보조 요소는 후속 확장 후보.**

체크포인트와 결승선은 시스템에서 자동 관리하므로 자유 배치 요소에 포함하지 않는다.

### 2.5 차량 사용 아이템

**D10 필수 1종(부스터) / D14 조건부 목표 총 3종**

| 아이템      | 작동 방식               | 개발 우선순위 |
| -------- | ------------------- | ------- |
| 부스터      | 일정 시간 차량 가속         | P0      |
| 망치       | 근거리 타격과 강한 넉백       | P0      |
| 따발총(기관총) | 전방 연사 및 작은 넉백       | P0      |
| 지뢰       | 바닥에 설치 후 접촉 시 폭발    | P1      |
| 커지기      | 차량 크기 확대 및 충돌 우위 확보 | P1      |
| 엽총       | 근거리 산탄 공격           | P2      |
| 로켓       | 전방 투사체 발사, 충돌 시 넉백  | P2      |

부스터, 망치, 기관총, 지뢰, 커지기, 엽총은 원작의 무기 목록에서 대응 항목이 확인된다.

로켓은 현재 기획서에서 제안한 구현 아이템으로, 원작의 독립된 아이템인지 추가 검증이 필요하다.

플레이어는 아이템을 최대 1개만 보유한다. 사용하거나 소진하면 슬롯이 비워진다.

아이템 보유, 사용 권한, 피격 효과는 서버가 검증한다.

클라이언트는 아이템 사용 요청, HUD, 사운드, VFX 등을 담당한다.

### 2.6 배경 맵

**이번 일정: 배경 1종. 두 번째 테마는 후속 확장 후보.**

- 장난감 작업실: 장난감 자동차·작업대·소품이 보이는 미니어처 환경 (수정 가능)
- 공중 도시: 높은 빌딩 또는 도시 공간 사이에 설치되는 공중 트랙 (수정 가능)

배경 맵마다 별도의 트랙 물리나 연결 규칙을 만들지 않는다.

맵은 매치 시작 전에 선택되며 한 매치 중에는 변경되지 않는다.

### 2.7 콘텐츠 목표와 출시 필수

아래 수량은 원안 대비 **D14 조건부 목표**다. D10에는 트랙 3종·부스터 1종·범퍼 1종·보조 2종·맵/차량 1종으로 매치를 끝내는 것을 우선한다. D5/D10 실패 시 추가 콘텐츠를 보류하고 출시 포함/보류를 명시한다.

| 트랙 조각     | 3종 |    5종 |
| 트랙 위험 요소  | 1종 |    2종 |
| 트랙 보조 요소  | 2종 |    2종 |
| 차량 사용 아이템 | 1종 |    3종 |

| 차량 외형     | 1종 |    1종 |

## 3. 핵심 플레이 사이클

### 3.1 전체 흐름

로비 → 맵 선택 및 준비 → 트랙 선택·건설 → 위험 요소·보조 요소 배치 → 레이싱 → 체크포인트 점수 정산 → 목표 점수 확인 → 트랙 확장 또는 최종 결과

한 매치의 권장 진행 시간은 **약 10\~15분**이다. 실제 시간은 참가 인원과 목표 점수에 따라 달라진다.

### 3.2 로비 단계

- 호스트가 맵 테마를 선택한다.
- 호스트가 최대 인원수와 목표 점수를 설정한다.
- 2\~4명의 플레이어가 입장한다.
- 각 플레이어는 차량 외형을 선택한다.
- 모든 플레이어가 준비 상태가 되면 시작한다.
- 네트워크는 우선 Listen Server로 구현한다.

### 3.3 트랙 건설 단계

초기에는 시작 지점을 생성하고, 플레이어 N명이 각각 트랙 한 조각을 선택한다.

이후 라운드에서도 참가 인원수만큼 트랙을 추가한다.

트랙 선택과 배치 준비는 **모든 플레이어가 동시에 수행**한다.

#### 배치 규칙

1. 플레이어에게 트랙 조각 후보 3개를 제시한다.
2. 모든 플레이어는 동시에 마우스로 트랙을 선택한다.
3. 각 플레이어는 Ghost Mesh로 배치할 위치와 방향을 확인한다.
4. 선택한 트랙을 기존 트랙 끝에 스냅 배치 요청한다.
5. 서버에서 배치 요청을 처리한다.
6. 배치가 확정되면 연결 지점이 갱신되고 모든 플레이어에게 복제된다.

단일 경로에 하나의 연결점만 존재하기 때문에 여러 플레이어의 배치 요청이 충돌할 수 있다.

이를 해결하기 위해 클라이언트의 선택과 미리보기는 동시 진행하되, 서버의 최종 연결 처리는 순차 수행한다.

이전에 접수한 조각이 배치되면 나머지 플레이어의 미리보기를 최신 연결점에 맞게 갱신한다.

**배치 제한 시간 초기값: 18초**

배치에 실패하거나 시간이 종료되면 서버는 제한된 기본 후보를 동일한 안전 규칙으로 검증해 보완한다. 모두 설치할 수 없으면 `ConstructionBlocked` 예외 결과로 종료하고 사유를 표시한다. 중첩 강제 스폰·무한 재시도는 하지 않는다. 정상 라운드만 N조각 추가 완료로 기록한다.

현재 끝점의 리비전보다 오래된 요청은 명시 거절한다. 선택을 보존하고 최신 Ghost에서 다시 확인한다. 서버 리비전 수신과 실제 트랙 Actor/충돌 준비를 구분해, 준비 확인 후 카운트다운을 시작한다.

트랙 건설 이후 위험 요소·보조 요소 배치 단계를 진행한다.

각 플레이어는 한 개씩 선택하여 설치하며, 서버에서 설치 가능 위치와 중복 배치를 검사한다.

### 3.4 레이싱 단계

- 모든 플레이어가 출발선에서 시작한다.
- 3초 카운트다운 후 조작이 활성화된다.
- 개별 3인칭 카메라를 사용한다.
- 차량 충돌, 장애물, 아이템 사용이 허용된다.
- 코스에서 추락하거나 차량이 파괴되면 일시적인 레이스 이탈 상태로 처리한다.
- 선두 플레이어가 다음 유효 체크포인트를 통과할 때 이탈한 플레이어를 안전한 복귀 위치로 이동시킨다.
- 모든 차량이 이탈하거나 선두가 진행하지 못하는 상황을 위한 별도 복구 규칙을 둔다.
- 체크포인트는 지정된 순서대로 통과한다.
- 서버가 결승선 통과를 검사한다.

트랙 조각당 체크포인트 하나를 두는 방안을 우선 검토한다.

선두와 일정 거리 이상 벌어지면 서버가 해당 플레이어를 자동 탈락시킨다. 기본 레이스에서는 일시적인 이탈 상태로 처리하고, 선두가 다음 유효 체크포인트를 통과할 때 기존 추락·파괴 규칙처럼 안전한 위치로 복귀시킨다. 거리 기준의 세부 정의는 7절에서 관리한다.

### 3.5 라운드 정산

점수는 체크포인트 도달 순서에 따라 계산한다.

| 참가 인원 | 체크포인트 도달 순위별 점수   |
| ----- | ----------------- |
| 2명    | 2점 / 1점           |
| 3명    | 3점 / 2점 / 1점      |
| 4명    | 4점 / 3점 / 2점 / 1점 |

체크포인트에서 탈락 또는 복귀로 구간을 건너뛴 플레이어는 해당 체크포인트의 점수를 받지 않는다.

동일 플레이어가 같은 체크포인트 점수를 한 라운드에 중복 획득하지 못하도록 서버에서 관리한다.

기본 목표 점수는 다음과 같이 제안한다.

| 인원 | 초기 목표 점수 |
| -- | -------: |
| 2명 |      20점 |
| 3명 |      35점 |
| 4명 |      50점 |

위 수치는 밸런스 테스트 전 가설값이다.

**라운드 종료 시** 목표 점수에 단독 도달한 플레이어를 최종 우승자로 판정한다. 레이스 도중 점수 초과만으로 매치를 즉시 끝내지 않는다.

한 라운드 종료 시 두 명 이상 목표 점수를 넘으면 서든데스를 진행한다.

이전 라운드의 체크포인트도 이후 레이스에서 다시 점수를 지급하므로, 트랙이 확장될수록 점수가 빠르게 쌓인다. 목표 점수와 한 매치의 평균 길이를 플레이테스트로 조절해야 한다.

무한 경기 방지를 위한 라운드 수 또는 총 트랙 수 상한도 둔다.

### 3.6 서든데스

현재까지 조립된 전체 트랙을 사용하여 서든데스 레이싱을 진행한다.

- 신규 트랙을 추가하지 않는다.
- 추락하거나 차량이 파괴되면 복귀하지 않는다.
- 끝까지 살아남은 순서 또는 결승선 통과 순서로 순위를 결정한다.
- 모두 탈락했을 경우 탈락 순서를 역순으로 계산한다.
- 동시에 탈락했을 경우 서버가 기록한 진행도와 시간을 비교한다.

서든데스에서도 선두와 일정 거리 이상 벌어지면 자동 탈락하며, 다른 탈락 원인과 마찬가지로 복귀하지 않는다.

### 3.7 트랙 확장

레이스가 종료되면 기존 결승선은 체크포인트로 전환된다.

기존 트랙 끝에 참가 인원수 N만큼 새로운 조각을 추가한다.

모든 플레이어는 다음 레이스에서도 최초 출발선부터 주행한다.

기존 트랙과 설치한 위험 요소·보조 요소는 유지한다.

### 3.8 최종 정산

목표 점수 도달 또는 서든데스 종료 후 최종 우승자를 결정한다.

최종 결과 화면에는 플레이어별 누적 점수와 최종 순위를 표시한다.

이후 재경기 또는 로비 복귀를 선택한다.

| 라운드 | 누적 트랙 | 플레이 내용            |

## 6. 차량 조작 및 카메라

기본 입력은 W/S 가속·브레이크, A/D 조향, LShift 드리프트(후순위), SpaceBar 아이템 사용으로 구성한다.

차량 조작 개선에서 검증할 요소는 다음과 같다.

- 속도에 따른 조향 반응
- 조향 입력 종료 시 복귀 속도
- 충돌 후 차량 회전 및 안정화
- 횡방향 미끄러짐의 예측 가능성
- 카메라 회전 지연 및 충돌 회피
- 급커브에서의 전방 시야 확보
- 다운포스 및 접지 상태

카메라는 차량 뒤쪽의 약간 높은 위치에 둔다.

속도에 따라 FOV 또는 거리를 변화시키되 과도한 카메라 흔들림은 피한다.

D3까지 차량 네트워크 이동뿐 아니라 원격 차량 충돌·임시 가속·넉백·텔레포트 후 제어 회복을 시험한다. D5에 효과 소비 계약을 확정하고 D7~D8 실제 아이템과 통합한다.

## 7. 탈락 및 복귀 규칙

**선두와의 거리 차에 따른 자동 탈락: 필수 레이싱 규칙(P0)**

| 상황 | 기본 레이스 | 서든데스 |
|---|---|---|
| 코스에서 추락 | 다음 유효 체크포인트에서 복귀 | 탈락, 복귀 없음 |
| 차량 파괴 | 다음 유효 체크포인트에서 복귀 | 탈락, 복귀 없음 |
| 선두보다 기준 거리 이상 뒤처짐 | 자동 탈락 후 다음 유효 체크포인트에서 복귀 | 자동 탈락, 복귀 없음 |
| 제한 시간 초과 | 미완주 처리 | 기록 비교 |

- 서버가 선두와 각 참가자의 거리 차를 판정하고 자동 탈락을 확정한다. 기본 레이스의 거리 차 탈락자는 추락·파괴와 같은 복귀 대기 경로를 사용한다.
- 선두의 다음 유효 체크포인트 통과 시 안전하게 복귀하며, 복귀로 건너뛴 체크포인트의 점수는 지급하지 않는다. 전원 이탈·선두 정지 시에는 기존 복구 규칙을 적용한다.
- **거리 측정 방식과 임계값은 미정**이다. 직선거리/코스 진행거리 중 사용할 기준, 선두 선정, 판정 주기와 복귀 후 판정 재개 조건을 구현 전에 확정하고 설정값으로 관리한다. 자동 탈락 규칙 자체를 후순위로 보류하지 않는다.
- 커브·고저차·차량 보정·선두 교체·복귀 직후의 잘못된 탈락과 중복 처리를 검증한다. 구현 계약은 개발명세 5.3절을 따른다.

## 8. 네트워크 아키텍처

### 8.1 서버 권한

서버는 다음 사항을 최종 결정한다.

- 라운드 시작 및 종료
- 현재 트랙 연결 구조
- 배치 권한과 배치 유효성
- 아이템 획득·사용·피격 결과
- 위험 요소 활성화 및 충돌 결과
- 체크포인트 및 복귀
- 완주 순위 및 점수

### 8.2 클라이언트 처리

- 차량 조작 입력
- 트랙 Ghost Mesh 미리보기
- 건설 전용 카메라
- 주행 카메라 및 HUD
- 아이템 사용 요청
- 로컬 사운드 및 VFX

### 8.3 상태 공유

GameMode는 서버 전용 게임 규칙과 상태 전환을 담당한다.

GameState는 라운드, 남은 시간, 현재 경기 상태와 같은 공통 정보를 복제한다.

PlayerState는 플레이어별 누적 점수, 완주 순위, 준비 상태 등 지속 정보를 관리한다.

트랙 관리 시스템은 연결 구조와 배치된 조각을 관리한다.

위험 요소는 종류에 따라 Actor 또는 Component로 구성하되, 서버가 핵심 판정을 수행한다.

경기 중 새 참가/재접속은 거부하고 로비에서 재접속한다. 호스트 종료 시 매치를 종료한다. 기존 참가자 이탈은 서버가 미배치·미완주 대기 상태에서 정리한다.

## 9. Technical Artist 시스템

### 9.1 Track Asset Validator

트랙 에셋이 게임 규칙을 만족하는지 검사하는 Editor 전용 도구를 개발한다.

검증 대상은 다음과 같다.

- 입구·출구 소켓 존재
- 연결 소켓 방향과 규격
- 주행 중심선 데이터
- 트랙 콜리전 및 채널
- 위험 요소 설치 슬롯
- 누락된 메시·머티리얼 참조
- 필수 트랙 메타데이터
- 트랙 간 오버랩 검사
- 스폰 및 체크포인트 안전 공간

미리보기의 빨간 Ghost와 거절 사유는 Runtime 배치 검사에서 제공한다. Editor Validator는 개별 에셋의 정적 규격을 검사하며 현재 월드의 실제 배치 판정을 대신하지 않는다.

### 9.2 자동화 범위

단순 문제 보고뿐 아니라 일부 설정을 자동 생성 또는 수정한다.

반복 임포트와 설정을 수작업으로 수행한 시간과 툴을 사용한 시간을 비교한다.

프로젝트에 실제로 사용하는 트랙과 위험 요소 에셋을 대상으로 검증하고 결과를 저장한다.

### 9.3 추가 TA 작업

- 임포트·에셋 정리 자동화
- 반복되는 머티리얼 구성 통합
- 머티리얼 인스턴스 활용
- Unreal Insights 및 GPU 프로파일러 기반 성능 분석

## 12. 범위 조절 기준

일정이 부족할 경우 다음 순서로 기능을 줄인다.

1. 두 번째 맵 테마
2. 차량 외형 추가
3. 아이템 P1·P2
4. 위험 요소 P1·P2
5. 특수 트랙
6. 드리프트 부스트 및 미니맵

끝까지 유지해야 하는 기능은 네트워크 플레이, 차량 이동, 마우스 트랙 건설, 트랙 확장, 체크포인트 복귀, 점수 정산과 최종 경기 완료다.

TA 툴도 범용화나 화려한 UI를 줄일 수는 있지만, 실제 에셋 검증과 사용 결과는 남긴다.

## 13. 품질 검증 및 포트폴리오 증거

개선 기능마다 원작 또는 기존 구현 방식과 비교할 수 있는 자료를 수집한다.

- 차량: 완주 시간, 충돌·추락 횟수, 조향 반응 테스트
- 카메라: 코너 인지 실패, 전방 시야 문제
- 트랙 건설: 배치 소요 시간, 중복 배치 및 충돌 처리 결과
- 위험 요소: 피격 판정과 위치 동기화 검증
- 아이템 HUD: 보유 아이템 식별 및 사용 오류
- 네트워크: 접속 인원, RTT, 패킷 손실, 상태 불일치
- TA 툴: 수동 검증 시간, 자동 검증 시간, 탐지 오류 수

모든 성능 수치는 테스트 빌드, 하드웨어, 인원과 측정 환경을 함께 기록한다.

외부 게임의 모델이나 텍스처를 활용할 경우 라이선스와 배포 가능 범위를 확인한다. 최종 공개 빌드에는 사용 권리가 확인된 리소스만 포함한다.
