# Make Way — TA 마이그레이션 실행계획

> v1.0 · 책임자 C · 관련 마일스톤: `01_TA_마일스톤_4주.md`  
> **Migration = 출처가 있는 기존 에셋을 UE5 게임에 쓸 수 있는 형태로 옮기고 검증하는 작업.** 신규 Editor 툴 개발 자체는 마이그레이션이 아니라 이를 지원하는 자동화 개발이다.

> **2026-10-22 실행 기준 보완:** 대상 엔진은 로컬에서 확인한 **5.8.3**, Runtime 모듈은 `MW`, 신규 Editor 모듈은 필요 시 `MWEditor`다. 일별 일정은 마일스톤 v1.1과 개발 순서 검토를 따른다. D1 조사 후 미확보 원본은 대체하고, D5 체크포인트/복귀 데이터 인수·실제 3PC 패키지 주행, D8 슬롯 정적 확인을 우선한다. 콘텐츠 추가 마감은 D14, D15부터 동결한다. 아래 포팅 절차는 실제 원본이 확인된 항목에만 적용하며 추가 인시를 배정하지 않는다.

## 1. 목적과 사실/가정 분리

### 확인 가능한 프로젝트 요구

- 게임에 필요한 첫 리소스: 차량 1종, 직선·커브·경사 트랙을 포함한 기본 트랙 3종; D15에 총 5종 목표.
- 트랙에는 **Entry/Exit 소켓, 연결 방향/규격, Collision, 중심선/체크포인트, 위험 요소 설치 Slot** 등 실제 게임 데이터가 필요.
- 위험 요소는 최소 2종, 보조 요소는 최소 2종, 아이템은 목표 3종; 리소스 수가 아닌 '실게임에서 작동하는가'로 판정.
- 별도의 기존 AssetFlow 자동 임포트/명명/머티리얼 작업이 개발 중이라고 사용자가 언급했다. **현 세션에서 AssetFlow 소스 아카이브를 검사하지 못했으므로 구현 완료 여부는 미검증**.

### 아직 확인되지 않은 사항

1. 실제 원본 파일 형식과 압축/추출 성공 범위.
2. 추출 원본의 배포/2차 가공 라이선스.
3. 현재 AssetFlow의 최신 작업 브랜치와 정상 작동 기능.
4. UE5.8.3 기준 실제 차량 물리/충돌 규격, 각 원본 모델의 축·스케일.

> **게이트:** 위 1·2를 확보하지 못해도 게임 개발은 합법적 대체 에셋/플레이스홀더로 진행한다. 접근 불가능한 원본의 '마이그레이션 완료'를 선언하지 않는다.

## 2. 마이그레이션 유형 분류

| 유형 | 출발점 → 대상 | 처리 방식 | 주의할 점 |
|---|---|---|---|
| 외부 프로젝트 에셋 이식 | 예: Unity에서 추출된 메시·텍스처 → UE5 StaticMesh/Texture/Material | 포맷 정리·Import·재질 구성·메타데이터 | 게임 로직·머티리얼 셰이더 동등성 자동 보장 안 됨 |
| 이미 추출된 파일 임포트 | FBX/OBJ/PNG 등 → UE5 | 언팩 단계 건너뛰고 검증·정리·임포트 | 원본 출처/라이선스 확인 필요 |
| UE↔UE Asset Migrate | UE 프로젝트 Content 에셋 → UE 프로젝트 Content | Unreal Migrate 또는 명시적 복사/재임포트 정책 | 연관된 C++ 코드, 플러그인, Project Settings까지 자동 이전된다고 가정하면 안 됨 |
| 규격/메타데이터 이식 | 원본 메시 + 작업용 설정 → UE5 트랙 DataAsset | 소켓/슬롯/경로/체크포인트 메타데이터 입력 | 추론 어려운 위치는 수동 확인과 게임플레이 테스트 필수 |

## 3. AssetFlow와 Track Validator의 역할 분리

| 단계 | 입력 | 담당 도구/과정 | 출력 | 실행 여부 선택 |
|---|---|---|---|---|
| S0 원본 수집/언팩 | 소유권 확인된 원본 | 외부 추출기/수동 (AssetFlow 지원 여부 조사) | 개별 메시·텍스처 파일 | 선택 |
| S1 목록·종류 분류 | 원본/기추출 파일 | AssetFlow 후보 기능 | 추적 가능한 Manifest | 선택 |
| S2 네이밍·폴더 정리 | Manifest | AssetFlow 후보 기능 | 정규화한 경로/이름 | 선택 |
| S3 UE5 Import | 정규화 파일 | AssetFlow Import / UE Import API | UE 에셋 | 선택 |
| S4 머티리얼 자동 구성 | Texture Map 집합 | AssetFlow Material 후보 기능 | Material Instance 및 참조 | 선택 |
| S5 트랙 메타데이터 | StaticMesh 및 수동 기준 | Track Metadata 작업 | TrackPieceDefinition | 필요 시 필수 |
| S6 에셋 규격 검증 | UE 에셋 + 메타데이터 | Track Asset Validator | Pass/Fail + 사유 로그 | 게임에 쓸 트랙은 필수 |
| S7 통합/승인 | Pass 에셋 | B 배치·A 차량 실주행 검증 | `Approved` 목록 | 실게임 도입 시 필수 |

### 선택 조합 (전체를 매번 돌리지 않는다)

- **A. 풀 파이프라인:** S0→S1→S2→S3→S4→S5→S6→S7 (추출 원본이 합법적으로 존재하고 전부 필요할 때).
- **B. 추출·분류까지만:** S0→S1→S2; UE5 에셋 만들지 않음 (분류 결과물을 다른 작업자에게 넘길 때).
- **C. 추출·정리·임포트, 재질 수작업:** S0→S1→S2→S3→S5→S6→S7.
- **D. 기추출 파일 직행:** S1→S2→S3→(선택 S4)→S5→S6→S7.
- **E. UE 원본 마이그레이션:** UE Asset Migrate→종속성 확인→S5→S6→S7.

**설계 원칙:** 하나의 마법 같은 '완전 자동화' 버튼보다 개별 단계의 Input/Output 계약·실패 복구·건너뛰기 가능성을 우선. S0은 도구에 지원 기능이 없으면 명시적으로 수동 수행.

## 4. 전달용 최소 데이터 계약

```text
AssetRecord
  SourceId             # 원본 경로/해시와 연결되는 고유 식별자
  OriginalPath         # 원본 파일 경로(공개 불가능한 경로는 공유 문서에서 마스킹)
  AssetClass           # Vehicle / Track / Hazard / Utility / Decoration / Texture
  TargetPath           # UE5 Content 경로
  SourceLicense        # 확인된 라이선스/미확인/배포 불가
  ImportMode           # 이미 추출됨 / 추출 후 / UE->UE
  ImportStatus         # Pending / Blocked / Imported / Validated / Approved
  ValidationNotes      # 오류·수동 수정 내용

TrackPieceDefinition (개념 설계)
  PieceId
  MeshRef
  EntryConnector, ExitConnector
  Width, AllowedSnapTolerance
  Path/CheckpointMetadata
  HazardSlots
  CollisionProfile
  Version
```

- `PieceId`는 임포트 과정에서 이름이 바뀌어도 유지되는 **게임플레이 식별자**로 분리하는 것을 권장.
- 유효한 경로로 임포트됐다는 사실은 '연결 가능한 트랙'이라는 의미가 아니다. S6/S7은 별도 검증.
- `AssetRecord`와 `TrackPieceDefinition`은 **제안 데이터 형태**이다. 현 AssetFlow의 실제 데이터 구조가 아님.

## 5. 원본/데이터 측면 변환 체크리스트

### 메시

- [ ] 축/Forward/Up 설정 및 UE cm 단위 환산 기록
- [ ] 피벗 위치가 소켓 기준과 일치하는지 확인
- [ ] Normal/Tangent/UV/버텍스 수 이상 여부 확인
- [ ] Nanite/LOD/Collision 사용 여부 기록(성능 근거 없는 무조건 적용 금지)
- [ ] 유효하지 않은 트랙 메시(구멍/역면/비주행 표면) 육안 + 차량으로 확인

### 텍스처/머티리얼

- [ ] Albedo/BaseColor, Normal, Roughness/Metallic, ORM Packing 채널 확인
- [ ] sRGB 사용 여부 점검 (일반적으로 색 텍스처 vs 선형 데이터 텍스처 분리)
- [ ] 재질 슬롯 수와 슬롯 이름 매칭
- [ ] 누락 Texture에 대한 실패/기본값 정책
- [ ] 동일 마스터 머티리얼의 인스턴스 재사용 가능 여부

### 게임플레이 메타데이터

- [ ] Entry/Exit Socket 명칭·Forward 일치
- [ ] 조립 간극/겹침·주행 폭 충족
- [ ] 안전한 체크포인트 순서/리스폰 영역
- [ ] Hazard Slot이 스폰·연결부를 막지 않는지 확인
- [ ] Collider가 차량·위험 요소에 의도한 반응을 하는지 시험

## 6. 실제 마이그레이션 일정과 인계

| 일 | 처리 대상 | B/A가 먼저 받을 것 | 실패 시 대체 |
|---|---|---|---|
| D1 | 원본/Manifest·AssetFlow 점검 | 1차 규격 문서, 스크린샷 | 검증된 공개/자작 에셋 목록 |
| D2 | 차량 1 + 직선 트랙 1 | D2 직선/차량 플레이스홀더와 소켓 기준 | UE 기본 Mesh로 동일 규격 제공 |
| D3 | 기본 트랙 3종 | 동일 PieceDefinition 계약의 3종 | 커브/경사 임시 메시 |
| D4~D5 | 참조/소켓/Collision 빠른 검사·통합 | 승인 목록 및 사용 금지 목록 | 수작업 체크리스트 검사 |
| D6~D10 | 범퍼/아이템 박스/가속 패드 리소스, Validator v1 | C 아이템 Actor, B 위험 슬롯 배치에 활용 | Primitive Collision+간단 Material |
| D11~D15 | 트랙 총 5종 목표, 머티리얼 인스턴스 정리 | Track DataAsset 승인 및 버전 동결 | 원래 플레이 가능한 P0 3종 유지 |
| D16~D18 | 패키지 누락, Editor 의존성, 프레임 비용 점검 | 릴리스 검증 결과 | 깨진 참조 기능 격리 |
| D19~D20 | 포트폴리오 증거, 재현 가이드/라이선스 표 | 재현 가능한 시연 | 미측정/미확인 결과 명시 |

**노력 예산:** 리소스 선별·이전 **23h**. Validator와 메타데이터 개발 **19h**, TA QA/증거 **6h**는 `01_TA_마일스톤_4주.md`에 별도 배정되어 있으며 **중복으로 48h를 추가하지 않는다**.

## 7. 오류 처리는 실패 범주별로 다르게

| 실패 | 탐지 | 처리 | 사용자에게 보일 내용 |
|---|---|---|---|
| 지원하지 않는 원본 포맷 | Import 전에 검사 | 해당 SourceId 건너뛰고 Blocked | `FORMAT_UNSUPPORTED` + 경로 |
| 이름 충돌/같은 에셋 재임포트 | TargetPath 및 SourceId 체크 | 덮어쓰기 전 Diff/명시 승인 | `TARGET_COLLISION` |
| 텍스처 누락 | 머티리얼 참조 검사 | 안전한 기본값 또는 수동 수정 | `MISSING_TEXTURE` |
| 트랙 Entry/Exit 누락 | Validator | 승인 금지, 소켓 배치 요청 | `MISSING_CONNECTOR` |
| Collider 없음/지나친 오버랩 | 정적 검사 + 차량 테스트 | 임시 Collision 또는 승인 보류 | `COLLISION_INVALID` |
| Editor 전용 코드 런타임 참조 | Package/Compile 검증 | Editor 모듈 의존 제거 | `EDITOR_DEPENDENCY` |
| 사용권 미확인 | Manifest License 필드 | 배포 빌드 제외, 대체 | `LICENSE_UNVERIFIED` |

## 9. 사용자 체감·성능 비교 (반드시 측정 후 작성)

| 관찰 대상 | 베이스라인 | 자동화 적용 | 증거 |
|---|---|---|---|
| 동일 5종 트랙 메타데이터 검사 | 수동 검사 시간 `T_manual` | Validator 검사 시간 `T_tool` | 스톱워치/로그, 입력 에셋 동일 |
| 누락 필드 발견 | 수동 미발견 항목 | 테스트용 오류 주입 검출 항목 | Fail 예시 원본과 리포트 |
| 재임포트 오류 | 경로/이름 충돌 수 | 재실행 시 충돌 수 | 전후 실행 로그 |
| Runtime 퍼포먼스 | 특정 장면 Frame ms/GPU/Memory | 같은 장면 동일 장비·빌드 조건 | Unreal Insights/Profiler 자료 |

절감률·FPS 변화는 **측정 전 공란**으로 둔다. 숫자를 가정해 기록하지 않는다.

## 10. 출구 게이트와 책임

- TA 엔진 Import 성공은 **마이그레이션 중간 상태**이며 '승인 완료'가 아니다.
- C가 메타데이터/Validation을 승인해도 A의 주행, B의 서버 배치가 실패하면 `Approved`로 올리지 않는다.
- `Approved` 에셋 변경 시 이전 승인 버전 보존, 변경 이유/재검증/담당자 기록.
- 리소스 공개 권한이 미확인되면 **공개 빌드에는 포함하지 않는다**.
