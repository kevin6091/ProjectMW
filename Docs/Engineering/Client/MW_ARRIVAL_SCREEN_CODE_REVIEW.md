# MWArrivalScreen 코드 점검

2026-11-23 · `feature/presentation-integration`의 설치 연출 작업 기준. 이 문서는 로딩 코드의 정적 점검 기록이다.

## 실제 실행 경로

- 로비 HUD의 출발 연출 콜백이 `Begin()`을 호출한다. GameInstance 서브시스템이 뷰포트에 Slate 가림막을 올리고 입력을 UI 전용으로 바꾼다. 지도 이동 동안 유지되는 코어 타이머와 이동·네트워크 실패 구독을 등록한다.
- 로딩 표지판은 `DefaultGame.ini`의 `LoadingWidgetClass`가 가리키는 WBP가 기본 외형을 소유한다. 가림막의 청록 배경과 WBP 실패 시의 예비 위젯, 재시도·방 나가기 판면은 C++의 Slate 코드가 소유한다.
- 지도 이동 제한은 단조 시계와 설정 `MapTravelTimeoutSeconds`로 판정한다. 기본값은 45초다. 목적지에 늦게 도착하면 가림을 유지한 채 현재 월드의 준비를 다시 시작한다. 목적지의 첫 장면 준비에는 별도의 표시 시간 제한이 있다.
- 목적지에서는 현재 월드·카메라와 경기 단계를 읽고, 선택 후보·배치 고스트·대기판·주행 차량의 준비 상태를 확인한다. 기본 셰이더와 텍스처 밉은 공개 전 필요하다. 추가 밉은 설정으로 제한된 시간만 기다린다. 렌더 완료 뒤 가림·실패 구독·타이머를 제거하고 로컬 입력을 복원한다.

## cpp 안의 FMWArrivalFrame

`MWArrivalScreen.h` 8줄에 전방 선언이 있고 `MWArrivalScreen.cpp` 83줄에 타입 정의가 있다. `TSharedPtr<FMWArrivalFrame>`를 보유한 `UMWArrivalScreen`만 이 구현을 생성하고 사용한다. 일반 C++ 클래스이며 UE 리플렉션 등록을 하는 `UCLASS`는 서브시스템 쪽이다. 이 방식은 렌더러·RHI 헤더를 공개 헤더에 전파하지 않는다. 설치된 UE 5.8에서도 `AutomationUtilsBlueprintLibrary.cpp` 27줄의 `FAutomationUtilsGameplayViewExtension`이 같은 파일 내 Scene View Extension 정의를 사용한다.

`git blame`에서 현재 클래스의 도입 커밋은 `f4e42a9` **출발 보고를 보존하고 목적지 첫 장면 준비 후 로딩을 해제**로 확인했다. 클래스는 뷰포트·씬·카메라·단계·세션·리비전을 묶어 이전 렌더 결과의 재사용을 막고, 렌더 스레드의 장면 패스 뒤 RHI GPU fence가 완료됐는지 알려 준다.

## 유지보수에서 고칠 지점

1. **역할 분리.** 현재 파일에 로딩 위젯 구성, 단계별 준비 조건, 실패 복구, GPU 샘플·펜스와 PIE 촬영 코드가 함께 있다. 렌더 검사 자체를 모듈 내부 `MWArrivalFrame.h/.cpp`로 옮기고 서브시스템에는 이동 수명과 공개 결정만 두면 리뷰 범위가 좁아진다. 공개 헤더의 전방 선언은 유지할 수 있다.
2. **준비 실패 제한 위치.** 출발 월드의 45초는 설정을 읽는다. 목적지 준비 제한은 `MWArrivalScreen.cpp` 453줄에서 `VisibleSeconds > 45.f`로 비교한다. 두 정책을 설정과 진단 문구에서 분리해 두면 현장 로그에서 이동 지연과 렌더 지연을 바로 구분할 수 있다.
3. **조명 수렴의 검증 범위.** 선택 장면의 24×16 색 샘플은 화면 전체를 축소해 평균적 변화를 판정한다. 개별 트랙의 작은 영역이 늦게 변하는 상황을 단독으로 검출한다는 보장은 없다. 이전 로딩 검증처럼 실제 첫 공개 프레임과 후속 프레임을 같은 시야로 비교해야 한다.

이번 커밋의 구현 범위는 트랙 확정 표시와 골조 연출이다.
