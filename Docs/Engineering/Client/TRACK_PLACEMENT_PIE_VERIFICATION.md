# 3인 PIE 트랙 확정 좌표 검증

2026-11-19, UE 5.8 Win64 Development Editor. 로컬 IP 리슨 서버 1명과 원격 클라이언트 2명을 한 에디터 프로세스(PID 8600)의 독립 창으로 실행했다. Cua Driver로 에디터의 Play를 누른 뒤, 세 참가자의 로비 준비·차량 확정·트랙 선택은 테스트 준비 스크립트로 진행했다. 설치 입력은 두 번째 원격 클라이언트(Client 2, Member 3)에서 수행했다.

## 실제 입력과 서버 대조

1. Member 3 창의 포인터를 직선 트랙의 연결 위치에 옮겼다. 고스트가 초록색으로 변하고 왼쪽 안내가 “스냅되었습니다. 좌클릭 또는 Space로 설치하세요.”로 바뀌었다.
2. 그 창에서 Cua Driver로 Space를 눌렀다. `UMWTrackPlacementViewComponent::HandleAccept`가 포인터를 다시 투영해 로컬 고스트를 갱신하고 RPC를 보내기 직전의 **액터 월드 트랜스폼**을 기록했다. 입력 좌표는 1280×722 게임 뷰포트 기준 (333, 276) px였다.
3. 리슨 서버의 `UEDPIE_0_L_Dev_Drive`에서 `PlacementSession.PlacedTracks`에 새로 추가된 조각 2의 `WorldTransform`과 서버 액터 트랜스폼을 각각 읽었다. Member 3의 원격 월드는 `UEDPIE_2_L_Dev_Drive`였다.

| 항목 | 확정 직전 로컬 고스트 | 서버 설치 기록 |
|---|---|---|
| 세션 / 코스 리비전 | 1 / 1 | 1 / 2 |
| 기존 조각 / 연결 포트 / 새 조각의 포트 | 1 / 0 / 0 | 1 / 0 / 0 |
| 위치 XYZ (cm) | 260.390000000, 450.000000000, 6000.000000000 | 260.3900000000003, 449.99999999999955, 6000 |
| 회전 쿼터니언 XYZW | 0, 0, −0.707106781, 0.707106781 | 0, 0, 0.707106750278, −0.707106812095 |
| 스케일 XYZ | 1, 1, 1 | 1, 1, 1 |

기록된 값의 위치 차이는 3차원 거리 약 5.7×10⁻¹³ cm로, 0.000001 cm 정밀도에서 세 축 모두 일치했다. 정규화한 두 쿼터니언 내적의 절댓값으로 계산한 회전 차이는 약 0.000005°였다. 쿼터니언 q와 −q는 같은 자세를 표시한다. 서버 액터 위치도 설치 기록과 일치했고, 해당 클라이언트에 “설치했습니다. 다른 플레이어를 기다립니다.”가 표시됐다. 이 실행에서 설치한 정의는 `Asset.Track.Placeholder.Test` 한 종류다.

## 코드와 재검증 위치

- `Source/MW/Gameplay/Construction/MWTrackPlacementViewComponent.cpp`의 `HandleAccept`에 에디터 전용 `-MWVerifyTrackPlacement` 진단을 추가했다. 평소에는 꺼져 있다. 마지막 스냅 판정과 `ServerPlaceTrack` 사이에 월드·멤버·세션·코스 리비전·입력 픽셀·연결 포트·고스트 위치·회전·스케일을 남긴다.
- 서버는 기존 `MWTrackConstructionPlacement.cpp`의 설치 경로를 사용한다. 확정은 서버 로그의 `Placed piece=2 member=3 target=1/0 source=0`로 대응시켰다. 서버 상태에서 조각 ID와 연결 포트를 확인한 뒤 저장 자세와 실물 액터를 각각 비교했다.
- 03:54:19.911 UTC에 로컬 확정 로그가 남았고, 03:54:19.935 UTC에 서버가 조각 2를 기록했다. 같은 프로세스의 관측 시각이다.
