# 완주 점수 화면과 카메라 연출 검토

## 영상 기준

- 10월 30일 영상 02:30에는 카메라가 주행 시점에서 점수판으로 넘어가고 체크포인트별 점수가 선수 열에 누적된다. 02:35에는 순위 보너스를 적용한다. 02:40에는 코스 확장용 트랙 선택으로 넘어간다.
- 10:50에는 최종 순위를 보여 준다. 11:15의 경기 개요와 XP는 별도 화면이다. 라운드 점수, 최종 순위, 성장 보상은 각자 해당 데이터가 있을 때 표시하는 단계로 구분한다.

## 현재 확인한 구현

| 기준 | 확인한 내용 |
| --- | --- |
| `e05bd00`의 `MWTrackRuntimeSubsystem.cpp::ProcessRaceTrigger` | 서버가 차량별 체크포인트 개수, 완주 여부와 경과 시간을 기록한다. 선수별 체크포인트 도착 순서, 보너스, 누적 점수를 클라이언트로 보내는 경로는 없다. |
| `e05bd00`의 `MWGameplayGameState` | 테마·방 단계·카운트다운 시간이 복제된다. 기준 브랜치에서 확인한 경기 진입은 Racing까지다. |
| 팀원 `origin/Server/GameProgress`의 확인 기준 `4e1f657` | `RoundResults`와 `MatchResults` 열거형은 있다. 해당 단계를 진입시키는 완주 처리와 복제 점수 결과 객체는 이 리비전에서 발견되지 않았다. |
| `Docs/Shared/MakeWay_기획최종안.md` 6절 | 도착 순서와 참가 인원별 체크포인트 점수, 보너스 및 라운드 누적을 서버 규칙으로 명시한다. 단순 통과 개수나 개인 경과 시간으로는 이 표를 계산할 수 없다. |

## 브랜치 작업 경계와 검증

1. 경기 서버가 라운드 ID, 각 체크포인트의 지급 내역, 순위 보너스, 참가자 ID·색·누적 점수, 다음 단계, 연출 시작 서버 시각을 확정해 전달한다. 전원 완주·이탈·시간 종료 정책은 라운드를 소유하는 코드에서 처리한다.
2. `feature/race-results-presentation`에서 점수 WBP가 확정 값을 표시한다. 참가자 색은 프로젝트 팔레트를 사용하고, 글꼴과 배치는 WBP에서 편집한다. 문구는 같은 위치에서 교체하고 이전 문구의 페이드와 겹치지 않게 한다.
3. 각 창의 로컬 카메라가 현재 경기의 결승 조각을 기준으로 결과판을 바라본다. 재진입 시 받은 서버 시각으로 현재 연출 단계에 맞추고, 결과가 닫히거나 이동하면 기존 카메라와 입력 소유자를 복구한다.
4. Cua Driver 3인 PIE에서 정상 완주와 이탈 포함 라운드를 각각 재현한다. 세 창에서 단계별 점수와 최종 순위가 서버 값과 일치하고 입력·카메라가 정상 복구되는지 캡처와 로그로 확인한다.

현재는 영상 순서와 런타임 연동 지점까지 확인했다. 실경기 점수판과 시네마틱은 서버가 확정 결과를 제공하는 단계에서 연동한다.
