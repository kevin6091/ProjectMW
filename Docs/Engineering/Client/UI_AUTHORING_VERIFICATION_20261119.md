## 오류와 복귀

- 정상 3인 출발과 직접 보고 혼합 시험 모두 서버가 플레이어 1·2·3의 보고를 각각 한 번씩 수신했다. 세 번째 클라이언트의 트랙 메시를 제거한 시험에서 시스템은 `offer 1 (Asset.Track.Straight.Test) mesh/material`을 기록하고 오류 화면을 표시했다. Cua Driver로 로컬 재시도를 누르자 메시가 복구되고 해당 창만 다시 공개됐다. 이 시험에서도 서버 출발 보고는 총 3회였다.
- 같은 시험에서 첫 번째 원격 창을 출발 전에 최소화했다. 호스트가 먼저 공개됐고 해당 창은 복원 후 자기 카메라와 GPU 렌더를 확인한 뒤 공개됐다.
- 로컬 세션을 생성해 호스트가 방 나가기를 요청했다. 타이틀 복귀 상태가 WaitingForSession → Traveling → WorldReady → Hidden 순서로 진행됐다. 목적지는 L_Title, 로컬 뷰 타깃은 MWUCM_WorldRouteCamera, 활성 메뉴는 WBP_TitleRoot_UCM_Dev였다.
- 가림 중에 서버에서 세 명의 트랙 선택을 확정한 시험에서는 배치 세션 1의 고스트·설치 트랙 재질을 확인하고 TrackPlacement에서 공개했다. 최초 선택 세션의 렌더 신호는 사용하지 않았다.

## 화면별 확인

- **차량 선택** — Cua Driver로 운영 로비 세 번째 창의 SMIET를 좌클릭하고 우클릭했다. 서버 상태가 빈 ID → Asset.Vehicle.SMIET → 빈 ID로 바뀌었고 참가자 카드도 확정·선택 중으로 돌아왔다. 세 로컬 WBP 인스턴스의 하위 위젯을 열거해 PreviewNotice가 없음을 확인했다. 부모 WBP의 프리뷰 텍스트와 카드·참가자·마커의 사각 툴팁 등록을 제거했다.
- **트랙 입력과 단계 안내** — 같은 창에서 월드 후보를 클릭했다. `HoveredOfferId=1`과 `SelectedOfferId=1`이 일치했고 `bConfirmed=True`였다. 나머지 선택 후 세 창이 배치 단계로 전환됐다. 단계 표지판 표시 시간은 각 창의 로딩 해제 후 시작한다.
- **경기 대기판** — 3인 로비에서 시험용으로 출발 명단 확정 전에 시험 맵으로 이동해 PreparingRace를 유지했다. 호스트에서 실시간 명단의 긴 한글 이름·차량·대기 상태와 네 열을 확인했다. 로고 텍스처는 할당됐지만 저장된 Image Size가 0×0이라 보이지 않던 문제를 발견해 원본 1005×1005로 저장하고 같은 호스트 화면에서 다시 확인했다. 일반 경기 직행의 첫 공개 장면은 별도 차량 카메라 시험에서 확인했다.
- **아이템 슬롯** — 픽업 검증 맵에서 소유 Pawn을 실제 상자에 겹치게 하자 보유 값이 None에서 Booster로 바뀌었다. 룰렛 카드 전환과 부스터 정착을 기록하고, Cua Driver로 Space를 입력해 None 복귀와 사용 페이드 종료를 확인했다. 주행 중인 같은 PIE 창을 Cua Driver로 조절하고 엔진의 뷰포트 크기를 읽었다. 1280×720, 960×720(4:3), 1680×720(21:9), 800×450, 1920×1062에서 좌하단 슬롯과 우하단 계기판을 대조했다. 별도 게임 프로세스의 1920×1080 첫 주행 화면도 원본 해상도로 보관했다.
- **실행 범위** — 에디터·게임 Win64 Development를 빌드했다. 콘텐츠 쿠킹·배포본 실행, UVCS 서버 제출·수신 측 검증은 수행하지 않았다. 별도 클라이언트에서 배치 고스트가 있는 첫 화면도 확인했다. 설치 확정 입력 추가 시험에서는 Windows가 대상 PIE 창의 전경 활성화를 거부해 게임이 포인터 위치를 받지 못했다. 후속 3인 PIE에서 Member 3이 설치한 고스트와 서버 좌표를 대조했다. [설치 검증](TRACK_PLACEMENT_PIE_VERIFICATION.md)과 [로딩 직후 UI 재검증](ARRIVAL_PRESENTATION.md)에 최종 결과를 기록했다. 실제 통신 단절은 주입하지 않았다. 모든 화면의 변경 전 동일 조건 캡처는 확보하지 못했다. 로딩의 변경 전 세션 표본과 변경 후 창별 원본 이미지를 보관했다.

WBP 4개의 프로젝트 상대 경로, 크기, SHA-256과 대응 커밋은 `Docs/Reviews/FrontendIntegration/PR_ASSET_HANDOFF.csv`와 에셋 ZIP 안의 `ASSETS.csv`에서 확인할 수 있다. ZIP은 ProjectMW 루트를 기준으로 Content 경로를 보존한다.
