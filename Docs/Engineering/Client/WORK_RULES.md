# Client 개발 작업 규칙

공용 문서, `Docs/Engineering` 직속 문서, `Docs/Shared/Client,Server` 전체를 먼저 읽는다.

- 로컬 입력·카메라·입력 모드·UMG/HUD·Ghost·차량 표시·소유자 요청/예측을 담당한다.
- 점수·배치·아이템 결과는 복제된 서버 상태를 표시한다. 로컬 타이머/UI만으로 게임 규칙의 성공을 확정하지 않는다.
- 서버 RPC는 올바른 소유권 경로를 사용한다. 새 RPC나 검증/복제 계약을 추가하면 Server 지침을 추가로 읽는다.
- UI는 생성 시 현재 상태를 반영하고 변경 이벤트를 연결한다. 원격 클라이언트와 Listen Host의 갱신 경로를 모두 확인한다.
- 복제 수신·Actor 생성·에셋/충돌 준비 순서를 가정하지 않는다. 현재 명세의 리비전·준비 확인·요청 거절 피드백을 유지한다.
- 새 아이콘/재질/VFX 등 에셋 제작을 포함하면 Art/TA 필독도 적용한다. 기존 값을 표시하는 화면 수정만으로 관계없는 에셋 작업을 확장하지 않는다.
- 실제 변경 범위에 맞춰 입력·화면·카메라·소유자/원격 표시·재생성/상태 전환을 검증한다.
