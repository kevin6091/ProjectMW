# 트랙 스냅 클릭과 원격 Q/E 회전 검증

2026-11-23 KST · UE 5.8 Win64 Development Editor · 설원 `L_Dev_Drive` · 리슨 호스트와 클라이언트 2명

## 수정 위치

`Source/MW/Gameplay/Construction/MWTrackPlacementViewComponent.cpp`의 `UpdateLocalPreview`는 고스트가 스냅 목표에 닿았을 때 연결 색상과 안내를 바꾼다. 포인터를 잠시 읽을 수 없는 상태에서도 마지막 목표까지 보간을 마친다. `HandleAccept`는 클릭 시점의 포인터로 기존 방식대로 설치 후보를 다시 찾고, 그 좌표로 고스트의 표시를 즉시 맞춘 뒤 기존 서버 요청을 보낸다. `BlendGhostPose`는 원격 창에서도 자유 자세를 두 포트의 중앙 기준으로 보간한다. 스냅 진입과 이탈에는 기존 전환별 기준점을 사용한다.

## 3인 PIE 결과

Editor 빌드 성공. UVCS `cs:64`의 UI 인계 에셋 10개와 로컬 파일의 서버 해시 일치를 확인했다. Cua Driver로 일반 로비에서 준비, FRED·DOUG·UFOLOGY 선택, 트랙 선택, 직선(P1)·45도 곡선(P3)·경사(P2) 설치를 진행했다. 관측 스크립트는 세 창의 상태와 좌표만 읽었다.

| 입력 창과 조각 | 클릭 직전 표시와 판정 차이 | 클릭 직후 표시와 판정 차이 | 서버 좌표와 클릭 판정 차이 |
| --- | ---: | ---: | ---: |
| P1 직선 | 13,221.390cm | 0.000000cm | 0.000001cm 미만 |
| P3 45도 곡선 | 14,090.385cm | 0.000000cm | 0.000001cm 미만 |
| P2 경사 | 15,753.433cm | 0.000000cm | 0.000001cm 미만 |

포인터를 멀리 옮긴 뒤 바로 클릭해 이동 중인 고스트에서도 재판정 경로를 탔다. 클릭 전에는 이동 중인 표시가 포인터보다 늦게 도착할 수 있다. 위치 오차는 서버 로그의 6자리 정밀도를 기준으로 대조했다. 시작·종료 조각을 포함한 코스가 5조각으로 완성됐고, 세 창 모두 시작 조각의 배정 위치에서 소유 차량으로 `Racing`에 진입했다.

| P3 곡선 고스트를 본 창 | 이전 Q / E 포트 중심 이동 최대 | 수정 후 Q / E 포트 중심 이동 최대 |
| --- | ---: | ---: |
| P1 원격 | 1495.279 / 1522.826cm | 0.002 / 0.003cm |
| P2 원격 | 1495.279 / 1522.826cm | 0.002 / 0.003cm |
| P3 소유 | 0.001 / 0.001cm | 0.000 / 0.001cm |

자유 배치 영역에 포인터를 고정한 뒤 Q와 E를 한 번씩 눌렀다. 각 입력 직전부터 0.72초 동안 두 포트 중앙의 최대 이동 거리를 계산했다. P2와 P3 창을 확대해 각각의 입력을 확인했으며, P2 Racing 진입의 UE DPI는 약 0.926, P1과 P3은 약 0.444였다. 최대화로 일부 창에서 비디오 메모리 경고가 떴다.
