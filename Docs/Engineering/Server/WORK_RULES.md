# Server 개발 작업 규칙

공용 문서, `Docs/Engineering` 직속 문서, `Docs/Shared/Client,Server` 전체를 먼저 읽는다.

- Listen Server의 GameMode·서버 배치·체크포인트/점수·아이템 판정·매치/접속 규칙·복제 계약이 대상이다. Dedicated Server 유무로 분야를 구분하지 않는다.
- 권한·소유권·Phase/Epoch·후보/대상·중복 요청·리비전·기한을 관련 명세에 따라 검증한다. 클라이언트가 최종 결과나 임의 클래스/배치 Transform을 확정하게 하지 않는다.
- 상태 변경과 요청 확정은 한 번만 처리한다. 실패 시 부분 등록을 남기거나 무한 대기로 다음 Phase를 막지 않는다.
- 지속 상태와 일시적 연출을 구분해 복제한다. 다른 Actor/RPC/OnRep의 도착 순서를 가정하지 않는다.
- 서버 계약을 바꾸면 Client 소비 코드/표시/거절 처리를 함께 확인한다. 이 경우 Client 지침도 먼저 읽는다.
- 소켓·배치 Footprint·슬롯·체크포인트/복귀 데이터 계약을 바꾸면 Art/TA 필독도 적용한다.
- 정상·거절·중복·오래된 요청·시간초과·이탈 등 변경에 직접 관련된 경로를 실제 서버/클라이언트 환경에서 검증하고 조건을 기록한다.
